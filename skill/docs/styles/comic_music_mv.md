## 三条核心实现规则（被纠正错误后的定案）

### 规则 1 · 角色一致性：参考图驱动，禁盲 t2i

❌ **错误做法**：每镜独立 text-to-image → 角色跨镜漂移

✅ **正确做法**：
1. 先出**一张角色设定图（character sheet）**，锁定角度/表情/服装基准
2. 后续每镜用 **cap-image-gen `--ref char_sheet.png`（image-edit 模式）** 改姿态/场景/光线，不重新 t2i
3. 每镜多采样 2–4 版，挑与参考图最接近的版本
4. 可选：新建一道轻量角色一致性目视 gate（参考 `pipeline/gate_check_palette.py` 结构）

⚠️ **未验证风险**：多角色同框复杂互动场景的一致性，无实测数据，遇到需专门验证后再定稿

---

### 规则 2 · 文字/花字层：全部代码叠加，不依赖模型带字出图

GPT-image-2「中文乱码 ~5%」的限制**只在"指望模型直接画出带文字的成片"时成立**。
本风格文字/字幕/Kinetic Typography 全部走代码层（HTML + GSAP），GPT-image-2 只负责插画/角色本体。

✅ **做法**：
- Kinetic Typography（整词砸屏 / 拆字动画 / 关键词高亮）全在 GSAP 代码层实现
- 参考样片 V2/V3 的花字手法可直接还原，但遵守项目可读性铁律（控制闪烁频率，不复刻 V3 高频闪烁反面案例）
- 工具：`pipeline/p004_video/` 或新建 GSAP 场景

---

### 规则 3 · 音乐卡点：节拍检测驱动，与作曲能力无关

MP3 是**外部提供的成品音轨**时，需要的只是**检测节拍时间戳**，是成熟的音频分析问题。

✅ **做法**：
1. 用 `librosa.beat.beat_track` 或 `aubio` 提取 BPM + beat 时间戳序列
2. 分镜切点对齐到最近 beat，强拍/downbeat 优先对应硬切或特效强调
3. 卡点公式（来自参考样片 V3 唯一双重验证案例）：静音/低能量留白 → 第一个强拍硬切/特效释放（「留白蓄力 → 卡点释放」）

⚠️ **工程现状**：pipeline 暂无音频节拍检测模块，首次使用需新建（优先 librosa，复用现有 .venv）

## 结构/包装层：直接继承，可在以下点反超参考样片

| 包装元素 | 参考样片现状 | 本引擎做法 |
|---|---|---|
| 前慢后快宏观节奏 | V4 已验证 | 默认候选留存节拍结构 |
| 底部角色/配音标注条 | V2/V3 有 | 固定字号+位置+色板，多角色标准组件 |
| 片头标题卡 + 片尾落款 | 4 条无一齐全 | **两者都要** — 低成本超越点 |
| 色板 | 样片多冷色/深色 | **强制白底起手；禁蓝紫；禁 AI 味深色** |

## 仍未验证的风险点（不能假装已解决）

1. 多角色同框复杂互动下参考图驱动的一致性稳定性
2. 特效精细度（光效/粒子/故障色差）能否达到 AE 手调级别上限
3. 节拍检测模块首次使用须验证复杂编曲/变速歌曲的检测精度
