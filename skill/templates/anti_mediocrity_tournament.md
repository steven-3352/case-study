> **canonical**：抗平庸机制只此一处；`skill/docs/PROCESS.md` 与 `skill/quality/quality_registry.md` 只链接不复写。
> **对应质量门**：`QG-ANTI-MEDIOCRITY`（抗平庸·停划裁判 · 见 `skill/quality/quality_registry.md`）。
> **定位**：补「判合不合格/应不应付」类门禁的盲区——**它抓不到"平庸/不抓人"**。本门专治 satisficing（够用就停）。

> **元规则**：`QG-RAISE-3`——「过了停划裁判」的感觉本身就是标准定低了的信号，先把"抓人"目标抬 3 档再判。

## 🔴 标尺（先定这一节再用 · 账号主人拍，项目 agent 不得自作主张塞爆款）

裁判判"好"时，拿哪把尺？**当前默认 = B**（贴本号"糙而真/攒同路人/非播放量"战略）。

- **A 流量尺**：completion_3s / 完播 / 停划率 / 互动。⚠️ 可能把纪录片号带成套路号。
- **B 真实尺（默认）**：真实感 / 翻车张力 / founder 找方向叙事 / 情绪真不真。只借结构维度（钩子类型·位置、情绪弧、人设一致、结构），**删掉爆款/投流优化目标**。
- **C 分轨**：走量选题用 A，连载/纪录片用 B。

> 换尺只改本节；下游 rubric 的**结构维度不变**，变的只是"优化目标"那一句。

## 一、抗平庸五步（装在"脚本/创意"这一环）

1. **不准交一稿** → N 个**不同角度**独立并行竞写（钩子先行 / 故事先行 / 反常识 / 自嘲 / 不同情绪主色…）；角度必须真不同，不是同稿改字。
2. **裁判判"平不平庸"而非"好不好"**：**默认毙掉**，除非有"具体的、别人写不出的东西"。
3. **critic → 改** 循环，把地板往上顶（`QG-RAISE-3`：地板不是目标，抬 3 档）。
4. **强 shortlist**（2–3 个都过关且不同）→ **逐拍/逐镜 best-of 合成** 或回流给人点峰值。
5. **按赌注分级**：核心脚本上全套锦标赛；边角料一稿过（对齐 `skill/docs/PROCESS.md §6` 生产档位——探索/轻量默认一稿过，全量触发才上全锦标赛）。

**与「合规/应付」类门分工**：那类门判"够不够格/是否应付"（合规分）；本门判"平不平庸/抓不抓人"（效果分）。**两道都要过**。编剧还须同时过 `QG-SCRIPT-QUOTES`（用户原话 ≥4 条）。

## 二、抓人 RUBRIC（裁判打分表 · 创作工种最低出工门槛）

> 本 rubric 服务 D19 情绪曲线（`skill/quality/video_19dim_scorecard.md`）：情绪弧映射至留存节拍，VO 情绪标记量化。基准是地板，按 `QG-RAISE-3` 提升 3 档验收。

### A · 前 3s 钩子（必须命中一种停划机制）
- [ ] 秘密/坦白 · 反常识/打脸 · 高风险悬念 · 冲突画面直给
- [ ] **必带**：①情绪（羞耻/脆弱/火/后怕，非中性）②好奇缺口（逼人想知道后续）
- **禁**：平铺直叙介绍背景

### B · 口播是"说话"不是"旁白"
- [ ] 短句、断句（关键处一字一顿）· 口语语气词 · 情绪落差（同条 ≥3 转折）· 每句可标"怎么念"
- **禁**：解释感受（"最可怕的是…因为…"）、长复合句、匀速平读、书面词

### C · 情绪曲线
- [ ] 全片有起伏图，**顶点（必炸）+ 落点（必凉/必戳）** 两锚点单独验收；不许中段一路平

### D · 传播性
- [ ] ≥2 句能被单独截成封面/评论区金句

### E · 停划裁判（出工种前必过 · 逐句盘，命中任一即打回）
1. 这句会让人划走吗？ 2. 这句没情绪/是中性陈述吗？ 3. 这句像旁白解说不像人在说话吗？ 4. 顶点够炸吗？落点够凉吗？还是在"讲道理"？

> **达标线**：每句过 E 四问；A/B/C 全绿。不到线不准进下一工种。宁可重写，不出"合格但平"的稿。

## 三、诚实红线（与本号一致）
- 情绪再大，不把 AI/角色写成"故意使坏的反派"；真实感 > 戏剧化编造。
- **不夸大不实**（如不编时长/数据）——这条也是"平庸裁判"之外的独立红线，归 `fact_check.md`（`QG-INSIGHT-3FACTS` / 事实校验员）。

## 四、落地前必做（别照抄）

- **先跑一个真脚本试判**，别一次铺全线：单编剧"合格但太平" → 三角度擂台 + 停划裁判 → 逐拍 best-of，情绪显著抬升（已在实战条目验证）。
- 深抄同类项目具体实装前（如「并行生成 N → 裁判选最优」、人工签字闸 + ffprobe、多维钩子打分），先亲自读一遍源，核实真实存在 + 对齐细节，当作对同类项目的补充了解。
