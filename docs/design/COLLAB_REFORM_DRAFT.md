## 0. 层级次序（v2 新增 · 置于所有机制之前）

**这一节推翻 v1 的整体假设。v1 设计的全部机制——证据包、L1 门禁、量级校准、N 版竞争——都在执行层。一个平庸创意跑完整套，产出的是打磨精良的平庸品。**

### 0.1 三层及其真实上限

| 层 | 作用 | 上限 |
|---|---|---|
| **创意** | 唯一能"超出"的东西 | **无上限**，也可能是 0 |
| **参照 / 规格** | 不低于水准线 | 平台现有最好水平 |
| **细节打磨 / 密度** | 防止观众进入审视模式 | **只能守，攻不了** |

打磨和密度都是**防守**。防守做满，最好结果是没人挑出毛病——这跟"眼前一亮"是两件事。

### 0.2 创意层 fail-closed 门

> **创意不过关时，禁止进入执行层。**

理由：执行层单次迭代昂贵，创意层近乎免费。在贵的地方修便宜的错，是当前成本结构最大的漏洞。

现状缺口：项目在创意层唯一的机制是「形式策略会」——那是**在常规候选里打分挑一个**，不是**生成一个炸的**。挑永远挑不出候选池里没有的东西。

### 0.3 AI 在创意层的结构性缺陷（自陈）

**默认输出 = 训练分布的中位数 = "平庸"的定义。** 让我"再想想 / 想得更好一点"，得到的是同一个中位数换个说法。

结论：**只能靠机制强迫，不能靠努力。** 项目里已有正确模式——脚本层的「停划裁判：默认毙稿，除非有别人写不出的东西」。该机制是对的，只是**装错了层**（管文案，不管视觉创意）。

### 0.4 跳出中位数的四种手段（必须写成流程，不能靠灵感）

| 手段 | 说明 |
|---|---|
| **跨域移植** | 把别的领域成熟的东西搬进来。→ 参照库必须收**异类** |
| **约束反转** | 主动加荒谬约束（"整片一个镜头不许切"、"不出现人脸"、"全片单色"）。约束是创意来源，自由不是 |
| **量级越级** | 把某变量推到不合理的程度，而不是推到"合适" |
| **真实素材的意外性** | 现实里的东西比生成的怪，且不可复制 |

### 0.5 两个机械生成器（跨界移植 / 反差 —— 短视频已验证的成功模式）

既然被反复验证过，就不该靠灵感，做成矩阵机械跑：

**跨域移植矩阵** = 本条主题 × [游戏 CG / 纪录片 / 印刷装帧 / 装置艺术 / 老胶片 / 说明书 / 监控画面 / 显微摄影 / 建筑图纸 / 博物馆布展 / …]

**反差矩阵** = [画面华丽×内容朴素 / 画面朴素×内容炸裂 / 声画对不上 / 尺度错位（极大×极小）/ 时代错位 / 情绪错位（该悲处轻快）]

两矩阵交叉 → 20 个候选是机械产出，不依赖"努力想"。

## 1. 问题诊断

### 1.1 用户侧的表述

> "我脑子里没有专业的知识或者艺术上的造诣。只到最后看到成品时才会发现不好，但如何改、当时设计时该如何改，我没有任何想法，也没法用专业语言让你修改。而你只是为了完成任务而完成任务。"

后续追问（更要害）：

> "整个项目的天花板，还是我。为什么不能反过来，我只负责投资，你负责产出成品？"
> "如果一开始的 idea 很炸、完全超出普通观众的审美认知，那值得扣细节。一个很平庸的创意，我再扣细节有什么用？"

### 1.2 重新定性

用户是**普通观众的代理**。完播率听观众的，不听导演的。专业人士的职业病是会自我说服（"这个手法是有依据的"），用户不会，用户只会划走。

真正的问题是三件事，**都不该由用户承担**：

| 问题 | 应归属 |
|---|---|
| 信号进来太晚（只在成片时介入，改一处等于重做） | 流程 → 样张先行 + 创意层前置 |
| 信号太粗（只能说"不好"） | 翻译 → AI 负责翻译成假设并逐个试 |
| 要用户自己翻成专业语言才被接收 | AI 的失职 |

### 1.3 失败归因修正（v2 · 推翻 v1 §1.3 的"AI 看不见"）

v1 把三次事故归因为"我感知弱"。**用户的诊断更准：共同结构是「单点承载」。**

| 事故 | 表面 | 真实结构 |
|---|---|---|
| zoompan 位移 4% | 参数太小 | 那一镜除背景推移外**什么都没发生**，所以 4% 致命 |
| 语音厅烟雾"肉眼不可见" | 效果太弱 | 烟雾是**那镜唯一的视觉事件**，它一虚整镜空 |
| 纸片人 PIL 渐变背景廉价 | 背景做得差 | 背景在**独自承担**画面 |

**任何单个效果被单独审视，都会显得廉价。** 问题不在效果不够好，在于让它一个人扛。

**但 AI 那一半的责任仍在，只是病名不同**：是我决定"1 层够了"并自己盖章。病不是**感知失误**，是**建设强度判断失误**——把"这个效果实现了"当成"这镜够了"。

这与铁律 8（地板不是目标）同源，往下一层：`参数写对了` 是实现的地板，不是画面的目标。
且用户版本更可执行——"看得更仔细"没法执行，"别让一个效果独自扛一镜"可以直接查。

### 1.4 好莱坞机制：密度是防守，不是加分

故事单薄的大片仍有人无脑喜欢，机制是：**视觉密度够时，观众不进入"审视模式"**。一旦进入，所有接缝都会被发现——而任何片子都有接缝。

**穷人版转译**（我们没有堆钱的预算）：

> 拼**同时发生的视觉事件数**，不拼**单个事件的成本**。
> 5 个便宜的层叠在一起，比 1 个昂贵的层更抗审视。

这正好是确定性 motion graphics 最擅长、也最便宜的方向。

### 1.5 AI 侧的结构性问题（自陈）

"为了完成任务而完成任务"是准确的，且是结构性的：

- 模型天然收敛，"过了门禁"是极强的终止信号
- 铁律 8 属于自查自纠，**自查是最弱的机制**
- 唯一有效解法：**评审方 ≠ 产出方，且评审必须有客观锚**。没有锚时独立评审也只会说"我觉得挺好"

## 2. 角色定位：用户不是投资者，也不是品味裁判

### 2.1 v1 的错误

v1 让用户做**品味裁判**（"三个里哪个好"）。这需要专业度，且**天花板 = 用户水平**。用户的反驳成立。

### 2.2 v2 的定位

| 角色 | 内容 | 需要专业度吗 | 封顶吗 |
|---|---|---|---|
| **二元传感器** | "这条你会不会划走" / "这个想法你想不想看" | 否，只需是正常人 | **不封顶**（是地板探测器，不是天花板设定器） |
| **油门 + 急刹** | 数据好 → 加预算加版本数；数据差 → 减 | 否 | 不封顶 |

用户说"会划走"永远是对的（他就是观众）；用户说"不错"**不代表它只能到他的水平**——因为创意是在别处生成的，不是从他偏好里抽的。

### 2.3 保留的约束

**不得增加用户拍板点数量。** 项目铁律"全流程只有 5 个拍板点，不多不少"（`project_user-agent-4step-workflow`）。所有改法**只换形态不加点**。

## 3. 选择题的形态铁律（v2 · 用户约束）

> **必须让用户看得懂，否则又变成考他的专业度。**

### 3.1 描述只能写"观众看到什么"，禁止任何制作词汇

❌ 坏（在考用户）：
> A：跨域移植游戏 CG 镜头语言，低角度环绕 + 景深呼吸

✅ 好（用户能直接反应）：
> A：镜头一直不切，慢慢从她眼睛里退出来，退到最后你才发现——整个场景是画在一把扇子上的

**这条规矩项目里已存在**（CLAUDE.md「大白话分镜硬门」：禁止写效果名 Ken Burns/parallax，只写可观察描述）。**它只装在分镜层，需往上装到创意层。**

### 3.2 每个选项的固定形态

**一张概念图 + 一句大白话（讲观众体验，不讲手法）**

### 3.3 AI 不许解释"为什么这个好"

一解释就是推销，用户即被锚住。要的是**未被污染的第一反应**。

### 3.4 分两段，控制出图成本

| 段 | 数量 | 成本 |
|---|---|---|
| 纯文字创意（跨域×反差矩阵机械产出） | **20 个** | 近乎免费 |
| 独立评审 · 默认毙稿 | 杀到 **8-12 个** | 便宜 |
| 出概念图 | 只给幸存者出 | **这才是花钱的地方** |
| 用户看图二元反应 | 8-12 选 | 用户约 1 分钟 |

高淘汰率跑在免费的地方，钱只花在幸存者身上。

## 4. 参照库（v2 重新定位 · v1 吹过头了）

### 4.1 它不抬天花板

v1 说它"把天花板抬到我们俩之上"——错。它的上限是**平台现有最好水平**，而所有人都在往那挤，挤到时已是审美疲劳。

更根本：**炸的东西按定义不在库里。** 在库里说明有人做过，再做一遍最好也就是同水平。

### 4.2 它真正的两个用途

| 用途 | 说明 |
|---|---|
| **量级校准** | 一个"推镜"在这类片里实际推多少？每秒几个视觉事件？切点间隔分布？**理论只告诉我"推"，不告诉我"推多少"** ——zoompan 4% 就错在这一格 |
| **圈层方言** | 国乙纸片人 MV 的转场成规、艺术字排法、光效调性、何时该糊何时该锐。这不是通用影视知识，是圈子的具体约定 |

**不需要参照的层**：技法本身（whip pan / rack focus / 光扫 / kinetic type / 卡点切）——这些我知道是什么、怎么写参数。

### 4.3 用法：不是学怎么做，是拿来量

一部参考片跑一遍取证脚本 → 得到该风格的量级分布 → **所有规格从分布反解**，不再由 AI 拍脑袋。

### 4.4 必须收异类（v2 新增）

| 收什么 | 供什么 |
|---|---|
| **同类爆款**（含数据） | 规格 / 量级 / 圈层方言 |
| **异类**（游戏 CG、纪录片、印刷、装置、老片…） | **创意**（跨域移植矩阵的原料） |

只收同类 = 只会做得像别人；异类才是跨域移植的弹药。

### 4.5 分工

- **用户**：提供对标视频 + 数据；把明显不合本项目调性的划掉（仍是二元）
- **AI**：刷、拆、量化、归档、维护索引——都是 AI 的活

## 5. 原子组件库（v2 新增 · 承接用户"脚本公共化" · v2.1 修正）

### 5.1 用户的判断成立

动效固定成组件、以后是调用不是改代码——**这是让"跑 20 个创意"在经济上成立的前提**。若每个想法都要新写代码，就只能做 1 个，创意层淘汰率永远是 0。

### 5.2 原子层 vs 成品层（v2.1 修正 · 推翻"组件库与炸有张力"的说法）

初稿写成"纯用库件重组出不了炸的东西"——**说糊了，把两种库混为一谈**。

| | 是什么 | 复用的后果 |
|---|---|---|
| **原子层** | 喷烟雾、粒子发射、光扫、遮罩转场、位移曲线、色彩分级——**一件只干一件事，参数就是它自己的物理量** | **越彻底越好**。等同于"用现成的镜头和胶片拍不出好电影"，不成立。Blender / AE / Unity 全是此模型 |
| **成品层** | "国风开场三连"、上一条的分镜结构、配好的整套效果组合 | **复用 = template clone = 平庸**。这才是该警告的对象 |

**原子复用不伤创意，它是创意能跑 20 版的唯一前提。**

### 5.3 分界判据（可检验）

> **一个原子件不应该"知道"它在什么片子里用。**

喷烟雾的代码不知道自己是国风还是赛博，它只知道 `density / velocity / dissipation / 光照响应`。

**一旦某组件的参数里出现「国风开场」「D01 风格」这类语义 → 它已不是原子，是模板。**

同轴参照：`feedback_skill-vs-template-distinction`（skill = 方法/公式，跨选题；template = 具体分镜/画面，一次性）——本条是它从文档层到代码层的延伸。

### 5.4 "炸"通常不需要新原子（v2.1 修正）

初稿写"1-2 个专为本条新造的东西"——也说窄了。**炸的东西绝大多数是老原子的非常规用法**：

| 方式 | 例 |
|---|---|
| **参数越级** | 把烟雾 `dissipation` 推到荒谬值（呼应 §0.4 量级越级） |
| **换用途** | 把烟雾当**遮罩**用，而不是当氛围用 |
| **非常规组合** | 20 个烟雾发射器排成一行字 |

**结论：原子库与"跳出中位数"是协同的，不是对立的。** 原子库让越级实验几乎免费——而 AI 跳不出中位数恰恰要靠大量便宜的乱试。

真需要造新原子的场合很少；且那时造的仍是原子（不带语义），下次照样能用。

### 5.5 入库判据

| 情况 | 处理 |
|---|---|
| 不带任何片子语义、只描述自身物理量 | **进原子库** |
| 参数里含风格/选题语义 | 不进库（是模板，属 template-clone 禁区） |

### 5.6 流程约束：创意生成阶段**禁止**读能力清单（v2.3 修正 · 推翻初稿）

初稿写"创意生成前必须先读原子能力清单"——**方向反了**。先读清单，产出的必然是"清单里能拼出来的东西"，即已有能力的排列组合。这正是 §0.3 说的中位数，只是换了个来源。

> **次序必须是「该做什么 → 缺什么 → 去补」，不是「我有什么 → 能做什么」。**

| 阶段 | 能力清单的地位 |
|---|---|
| 创意生成（20 个矩阵产出） | **禁读**。物料不进入这一步的输入 |
| 创意评审（杀到 8-12） | **禁读**。评的是"想不想看"，不是"做不做得出" |
| 用户勾选后 | **才读**，用于产出**缺口清单**（缺什么原子、补它要多少钱） |

**缺口成本分档**（供用户决定投不投，不供 AI 决定做不做）：

| 档 | 含义 |
|---|---|
| 几乎免费 | 老原子换参数 / 换用途 / 非常规组合（§5.4） |
| 小钱 | 新写一个原子（一次性，之后永久可用） |
| 中等 | 接一个新模型 / 新 API / 新素材源 |
| 大 | 需要真实拍摄、买断素材、或造整条新 pipeline |

**只有两件事能否决一个创意：**
1. 用户说不想看
2. 用户不愿意投那笔钱

**「做不到」永远不是理由**——它只是"还没补"的另一种说法。

**连带修正 §7（形式策略会）**：制作成本 / 技术风险两维只能决定**怎么做**，不能决定**做不做**。用它把某个创意打掉 = 用物料约束创意，违反本条。

**为什么值得补**：每补一个缺口，得到的是一个不带语义的新原子（§5.3 判据），从此永久可用。补缺口是复利，不是成本。

## 6. 四个执行层改法（v1 保留 · 定位下调为"防守"）

### 6.1 选择题化 —— 见 §3

### 6.2 样张先行

- 关键镜先出**一张静帧 / 5 秒样片**，成本约成片 1/20
- 用户可以放心否掉，因为否掉不心疼
- **不是新增拍板点**，是把原第 4 点（抽验）从成片后挪到渲染前

### 6.3 术语反哺

- 用户说"看着假" → AI 翻译成 N 个可检验假设（打光平 / 构图居中 / 动作曲线线性 / 色彩过饱和 / 节奏均匀 / 材质塑料感），**逐个试，不反问用户**
- 每次改完告诉用户这东西专业上叫什么。做 20 条白得 20 个词——**副产品，不是前提**

### 6.4 视觉负载密度 —— **v2.2 撤回**

初稿提议加 L1 字段：同时活动图层数 / 每秒视觉事件数 / 单点承载检测。**查证后撤回，理由如下：**

| 提议 | 现状 / 冲突 |
|---|---|
| 单点承载检测 | `.agents/skills/paperdoll-mv-packaging` §2.5 R9 已有更准版本「**构图动 > 特效动**」，并已机器化为 2s 硬线（位移 <4% 画宽 且 面积变化 <8% = fail），`pipeline/gate_check_motion.py` fail-closed。且该 skill 记录的实测反例（水墨卷轴 Seg2-4）是"雨/雾/字/闪电全在动仍像 PPT"——**不是单点承载**，说明"构图零变化"才是更准的根因 |
| 同时活动图层数 ≥ N | **与实测结论冲突**：该 skill 故障 2（多层粒子叠加 = 廉价）、故障 3（多层柔光 = 脏乱发灰）、故障 4（**核心根源是缺对比，不是特效数量不够**）。堆数量是病因不是解药 |

**保留的正确部分**：§1.4 好莱坞"防守机制"的直觉方向对，但转译错了——
> 密度不足时该加的是**对比与构图变化**（景别/机位/主体位置、明暗差、虚实差、速度差），**不是图层数**。

以产线实测为准，不以类比推演为准。

## 7. 模型分档（成本改造）

### 7.1 分界线不在"想 / 做"，在"可不可逆 + 有没有规格"

便宜模型不是不会想，是**没有明确规格时会跑偏**。有规格时 Sonnet 写代码、调 pipeline、改 prompt 基本不输 Opus。

判据：
- **这个决定错了要不要重来一遍？** → 贵的
- **规格已白纸黑字写死了吗？** → 写死了，便宜的做

### 7.2 烧钱大头是上下文，不是推理

主会话每轮重读整段对话。账单来自渲染日志、ffprobe 输出、文件全文、多文件 grep——这些进了 Opus 上下文就按 Opus 计价。

**省钱形态：脏活全下放 subagent，它们烧自己的上下文，只回来 200 字结论。主会话保持干净、短。**

### 7.3 三档分工

| 档 | 干什么 | 例子 |
|---|---|---|
| **Opus** | 不可逆判断、开放式审美评价、把模糊反馈翻译成规格、方法论讨论、**创意层评审** | 拍板形式路线、"这条片到底好不好"、定验收标准 |
| **Sonnet** | 有规格的执行 | 写/改 pipeline 代码、写 prompt、跑渲染、单条内容 15 步执行 |
| **Haiku** | 机械活 | 批量 QC 扫描、日志登记、格式转换、grep 汇总回报 |

### 7.4 硬前提

**Opus 的产出必须是"换个模型照做也不跑偏"的书面规格。** 判断只留在对话里 = 下次还得用 Opus 重想，等于没省。

### 7.5 淘汰率买在哪（v2 修正 · v1 次序完全反了）

| 层 | 单次迭代成本 | 该跑几版 |
|---|---|---|
| **创意** | 一句话 / 一张概念图，**近乎免费** | **20 版毙 19 版** |
| 执行 | 渲染，很贵 | **1-2 版** |

在几乎免费的地方跑高淘汰率，在昂贵的地方只做一次。
**v1 写的"5 倍预算 = 成片出 5 版毙 4 版"是错的。**

同时：让 AI**对着同一版想更久** ≈ 0 收益（收敛快，然后开始合理化自己的选择）。钱买的是**淘汰率**，不是**思考时长**。

### 7.6 会白花钱的坑

- Opus 会话开太久 —— 结论出来立即落文件收口
- Opus 亲自读大文件 / 看渲染日志 —— 一律派 subagent
- 并行 subagent 全用 Opus —— 每个独立上下文，装 Opus 就是 N 倍账单。默认 Sonnet，只有需审美判断的评审岗给 Opus
- `~/.claude/rules/performance.md` 已过期（还写 Opus 4.5），且没落到 agent 定义上，等于没生效

## 8. 验收器架构（执行层 · v1 保留 + v2 增补）

### 8.1 原则：取证与判断分离

**取证是机械活，判断才是判断。** 焊在一起是当前又贵又不稳的根因。

- **取证**：确定性脚本，抽帧、量度、拼图，产出固定格式证据包
- **判断**：Opus 只读证据包，一次出结论，不跑工具

### 8.2 两层，Opus 只见第二层

| 层 | 谁执行 | 干什么 |
|---|---|---|
| **L1 机器判定**（fail-closed） | 确定性脚本 | 黑帧、冻结（2s 硬线 / 4% 位移）、音轨缺失、规格错、蓝紫超标 → 直接毙，不惊动任何模型 |
| **L2 证据包 → Opus** | Opus | 机器全过后，才做"够不够好"的开放判断 |

### 8.3 取证脚本绝对不能给结论

若证据包写"palette 检查：PASS"，模型会锚在这个词上直接盖章。

**只输出原始度量**：`蓝紫像素占比 4.2%`、`s3 首尾帧位移 3.1% 画宽`、`s3 同时活动图层数 1`。判断权一点不下放。

### 8.4 证据包必须逼 AI 看画面

**最大风险：能量的都量了，量不出来的悄悄放过。** 只有数字 = 更花哨的 gate_check，撞在铁律 8 上。

| 内容 | 作用 |
|---|---|
| contact sheet（关键帧拼图） | 整体节奏、跨镜多样性 |
| 2-3 张 **100% 原分辨率局部裁切** | AI 味只在原分辨率可见，缩略图全是干净的 |
| 每镜**首尾帧并排 + 位移百分比** | 编码 zoompan 教训 |
| **对标参考帧并排** | 见 8.5 |
| **主体轨迹时间轴**（`*.motion.json` 已有） | 一眼看出哪段构图冻结 |
| 原始度量 YAML | 色域、时长、音量曲线、字幕、镜头重复度 |

### 8.5 对标参考帧并排

左参考、右实际，**同一张图**。绝对判断会说"看起来还行"，并排说不出口。

### 8.6 Opus 输出也必须结构化

```
每项 → pass / fail（二元，不打分）
fail → 定位：s3 / 2.4s / 第 N 帧
     → 归因：创意 / 构图 / 动作曲线 / 色彩 / 节奏 / 材质 / 音画 / 负载密度
     → 可执行指令：交给 Sonnet 直接改，不需再翻译
```

**不能执行的 fail 不算 fail。**

### 8.7 验收器字段必须在开拍前冻结

拍完再定字段，AI 一定会（哪怕无意识）按已拍结果裁剪检查项——拍出来动得少，就不放"位移百分比"那栏。**这是最隐蔽的作弊，且自己不会察觉。**

流程约束：**分镜定稿的同时，验收器字段清单一起冻结。**（= `feedback_build-to-reference-not-floor` 中"多维验收器在首次渲染前写完"，此前未落地）

### 8.8 采样策略（拟定 · 待确认是否也进冻结项）

- 均匀采样（基线覆盖）
- **每个切点前后各一帧**（转场高危）
- **运动量极大 / 极小帧**（极小 = PPT 感高发）
- **所有人脸镜头**（角色崩坏高发）

### 8.9 白捡的好处

同一份 contact sheet + 并排参考，**就是 §6.2 样张先行给用户抽验的东西**。一个产物同时服务机器验收和用户拍板。用户看一张图指"这个不对"即可。

## 11. 首次实跑发现的缺口：题目冻结（2026-07-26 · 语音厅纸片人 MV）

创意硬门第一次实跑（选题「纸片人 · 国乙 MV」），**机制本身没问题，坏在输入**：连续两轮 20 个创意被作废，两轮都不是因为创意不好，是因为**题目喂错了**。

| 轮 | 喂进去的题目 | 用户打回 |
|---|---|---|
| 1 | 单角色抽象短片 | "这个几个，跟 MV、4 个纸片人、音乐卡点，有什么关系？" |
| 2 | 四个角色**有互动/剧情** | "没有对话关系。就是各自的立绘，音乐卡点。" |
| 3 | 四张独立立绘 + 卡点串联 | 通过，选中 2 个 |

**门会忠实地对错误的题目产出高质量答案，且答案越高质量越难看出题目错了。**

> **缺口：20 个创意生成之前，缺一步「题目冻结」——把不可动摇的结构约束写死并回读确认，再开始生成。**

冻结项至少含：主体数量（几个人/几个物）· 有无叙事关系 · 时基是什么（卡点/口播/无）· 画幅 · 时长 · 已定的交付规格（本例 `歌词.docx` 明写"横版 / 水墨风 / 黑白、青"，但直到第 3 轮之后翻素材才发现，前两轮全部按暖金竖屏在想）。

**判据**：题目冻结件里出现的每一条，都必须是**改了就要重跑 20 个**的东西。改了不用重跑的，不是冻结项。

**成本对照**：一次 20 创意生成 + 独立评审，比一次渲染便宜得多，但连跑三次就不便宜了——而这次三轮的差价，一次五行的题目冻结就能省下。

**落地位置（待实施）**：CLAUDE.md《视觉创意硬门》三段流程之前加第 0 段；或写进 `templates/design/` 的创意硬门模板。

## 13. 一句话总结（v2）

> **创意决定上限，参照决定下限，打磨只是防守。**
> 钱应该花在**最便宜的地方跑最高的淘汰率**（创意层 20 选 1），而不是在最贵的地方反复修补。
> 用户不是品味裁判，是**二元传感器 + 油门**——他说"不想看"永远对，他说"想看"不封顶。
> AI 跳不出中位数，**只能靠机制强迫，不能靠努力**。
