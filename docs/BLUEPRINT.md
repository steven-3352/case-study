# AI 小系统获客引擎 · 总蓝图

> 用 AI 解决小老板每天都烦的问题 · 三平台 · 数字人起步 · 最终只负责选题和方向

## 1. 目标

| 项 | 定义 |
|----|------|
| 终态 | 你每周 <30 分钟：挑选小老板真实场景 + 定方向；其余生产/采集/报告自动化 |
| 起号 | Phase 0 备齐 pipeline → Phase 1 **Project-001 多形态发布测效果** → Phase 2 半自动 → Phase 3 闭环 |
| 原则 | 项目结果先于方法论；先用自己的项目；等私信转化；先人工干预，逐步自动化 |
| 决策 | 见 [DECISIONS.md](DECISIONS.md)（Q1–Q6 已锁定） |

## 1.1 内容定位

账号主线不是 AI 教程，也不是「分享遗忘的经验」。

核心方向是：

> 我用 AI 把小老板每天烦、重复、没人管的事，做成能跑的小系统。

每条内容都要尽量回答一个获客问题：

- 这个项目解决了哪类小老板的具体麻烦？
- 原来靠什么笨办法处理？
- AI 改造后变成什么样？
- 有没有真实项目画面：截图、录屏、表单、后台、流程？
- 看完的人会不会觉得「这东西我也想要」？

## 2. 系统分层

```
Layer 0  你          小老板场景选题(queue/topics.yaml) + 方向(月度一句话)
Layer 1  选题引擎     读历史 metrics + 规则 → 推荐选题（Phase 2+）
Layer 2  生产流水线   场景痛点 → 项目成品 → 数字人 → B-roll 拼接 → 三平台导出
Layer 3  发布采集     发布 → 48h/7d 指标 → metrics.csv
Layer 4  反馈修正     rules.yaml → 周度报告 → 下批方向
```

## 3. 项目模块

| 模块 | 路径 | 职责 | 自动化阶段 |
|------|------|------|-----------|
| **IP 配置** | `persona/` | 人设、禁用词、标签策略 | Phase 0 定稿 |
| **选题队列** | `queue/` | 小老板场景、项目改造、成品展示 | Phase 0 人工 → Phase 3 半自动 |
| **内容模板** | `templates/` | 场景痛点/项目成品/发布模板 | Phase 0 人工填 → Phase 1 AI 辅助 |
| **素材库** | `assets/` | 项目截图、录屏、B-roll、数字人、声音 | Phase 0 人工拍 → 持续积累 |
| **生产流水线** | `pipeline/` | 脚本→视频→导出 | Phase 0 全人工 → Phase 1 半自动 |
| **运营反馈** | `ops/` | 指标、规则、数据规范 | Phase 1 人工填表 → Phase 2 脚本 |
| **发布包** | `publish/` | 待发布成品+文案 | Phase 1 人工发 → Phase 2 定时 |
| **遗留工具** | `legacy/` | 旧 slides/TTS 生成器 | 仅作素材库，不作首发默认 |

## 4. 内容系列（前 20 条）

| 系列 | 目的 | 形态 |
|------|------|------|
| S1 小老板烦恼改造 | 主线获客，让用户觉得「我也有这个问题」 | 60s 视频 + 图文 |

| S5 真实项目复盘 | 增加真实感，说明交付取舍 | 视频号 / 小红书 |
| S6 需求诊断 | 引导用户说出自己的场景 | 评论互动 / 图文 |

旧的「踩坑」「成长日记」「老兵判断」可以作为表达手法保留，但不能成为内容主线。主线必须是具体小老板问题和 AI 小系统改造结果。

- [ ] 比旧素材包更「像自己的项目」，不像 AI 教程号
- [ ] metrics.csv 和 rules.yaml 就绪
