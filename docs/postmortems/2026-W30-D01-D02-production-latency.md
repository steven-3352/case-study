# W30 D01/D02 生产耗时复盘

> 日期：2026-07-19
> 范围：`2026-W30/D01`、`2026-W30/D02` 抖音配音成片
> 结论：两条片的必要返工守住了真实性和观赏性，但生产顺序、运行时校验和增量构建存在系统缺口。以后不得依靠操作者记忆规避。

## 1. 最终结果

| 项目 | 最终时长 | 内容结论 | 形式结果 | 发布前预测 |
|---|---:|---|---|---|
| D01 | 47.96s | 普通问法也发现风险；单点问法只是在开头优先核查核心能力 | 最长冻结 3.50s | B；3s 完播 61%–69%，完播 30%–37% |
| D02 | 52.48s | “换成人名”无稳定效果；事前验尸只证明改变回答组织方式 | 最长冻结 3.97s | B；3s 完播 64%–72%，完播 31%–38% |

两条均为 1080×1920、30fps、MiniMax 配音、烧录字幕、独立 SRT、CC0 SFX、无 BGM；无黑帧、无 ≥3s 异常静音。预测是 B 级估算，不是平台实绩。

## 2. 为什么耗时长

### 2.1 必要的质量成本

这些工作不能省；省掉会得到更快但不可外发的片。

1. **真实 A/B 推翻了原命题。** D01 不能再声称普通提示只会夸；D02 不能再声称把“我”换成“小林”会更客观。两条都必须重写内容边界和叙事。
2. **独立内容审核拦住了误导。** Reviewer 要求删除虚构经历、不可回查数据和超过实验所能支持的因果表述。
3. **终片审核拦住了静态幻灯片。** 初版 MP4 有 5–9s 冻结段，虽能播放、文件齐全，但违反每 2–4s 视觉变化的硬要求。
4. **按真实配音重排动作。** 最终 VO 比名义分镜长约 8–9.5s，必须把逐条盖章、路径推进、票据交换和 Prompt 落签延展到真实口播末端。

### 2.2 可避免的流程损耗

| 损耗 | 直接后果 | 根因 |
|---|---|---|
| 核心假设到脚本后才实测 | 洞察、脚本、分镜一起返工 | 没有 Stage 0 evidence spike |
| 审核前未建角色×版本覆盖矩阵 | 任务轮次过多，仍难确认是否漏岗 | 把“多任务”误当成“完整覆盖” |
| MiniMax 收到不支持的 `serious` | TTS 失败后才定位参数 | 没有供应商能力小样 |
| MiniMax 失败可静默回退 Edge | 可能生成错误音色再继续生产 | 生产 TTS 未 fail-closed |
| 分镜按 40/43s，VO 为 47.96/52.48s | 尾部动作提前结束，形成长冻结 | 动画只按名义时长设计 |
| gate 不检查最终 MP4 冻结 | 问题直到人工 Phase B 才暴露 | 机器 QC 缺动效密度项 |
| 两项目共用 `out/frames/prompt_save` | 并行捕获相互覆盖/冲突 | 中间产物未按 content_id 命名空间隔离 |
| 小改也全量重渲约 2,800 帧 | 每轮修改都付出完整渲染时间 | 没有逐场景内容哈希缓存 |
| 直接执行 gate 出现 palette import 问题 | 门禁命令受启动目录影响 | import 只支持单一路径 |
| Phase B 未强绑定终片哈希 | 重渲后旧评分可能被误用 | 评审对象身份未机器校验 |

## 3. 强制生产顺序

以后所有视频项目按以下顺序执行，禁止并行穿透门禁：

1. **Stage 0 · Evidence spike**：用最小真实调用验证核心命题，保存输入、输出、时间、模型、参数、哈希和结论边界。命题不成立时先换命题，禁止先写完整脚本和分镜。
2. **内容门**：洞察、事实边界、脚本和内容 scorecard 通过后才允许生产 TTS。
3. **审核覆盖计划**：在派 reviewer 前建立“角色 × 内容版本 × 形式版本 × 阶段”矩阵；每个强制角色恰有规定数量的独立 reviewer，禁止靠追加任务碰运气补齐。
4. **TTS dry-run**：每个 provider/voice/emotion 组合先合成一句 5–10s 小样；参数合法、音色正确、凭证可用后才合成长稿。生产必须 `strict_provider: true`。
5. **真实时长驱动**：先获得 VO timing，再生成 runtime storyboard。每镜至少做 1.0× 和 1.5× 时长压力测试；动作不能在 1.0× 口播结束前停止，1.5× 下不得出现失控遮挡。
6. **命名空间隔离**：帧、音频、临时 concat、缓存路径必须包含 `content_id + scene_id`；并行项目不得写同一目录。
7. **机器 QC**：在 Phase B 前自动检查 ffprobe、黑帧、静音、冻结、字幕、音轨和文件规格。任一失败直接返工，不消耗 reviewer。
8. **Phase B 终片评审**：评审输入必须记录 canonical MP4 的 SHA-256。终片字节变化即使文件名相同，也自动作废旧 Phase B 结论。
9. **Forecast 与外发**：内容门、形式门、机器 QC、终片绑定的独立评审均通过，且 `pre_publish_forecast >= B`，才可标 `approved`。

## 4. 自动门禁与责任归属

| 门禁 | 自动检查 | 失败回到 |
|---|---|---|
| Evidence | 核心 claim 有可复核实验及来源等级 | 选题深挖/事实校验 |
| TTS capability | provider、voice、emotion 小样；禁止静默回退 | 声音设计/生产脚本 |
| Runtime duration | runtime storyboard 来自真实 timing | 动画导演/构建脚本 |
| Namespace | 中间路径含 content_id/scene_id | 构建脚本 |
| Machine QC | 黑帧、静音、冻结 >4.00s、规格 | 动效/剪辑/音频 |
| Review identity | scorecard 的终片哈希等于当前 MP4 | 编排/gate |
| Release | forecast B+ 且两道门通过 | 对应未通过工种 |

## 5. 本次已完成的系统修复

- `gate_check.py`：`post_render/approve` 自动执行 FFmpeg `freezedetect`，超过 4.00s fail-closed；兼容两种 palette import 启动方式。
- `tts/gen_speech.py`：MiniMax emotion 白名单与别名归一；生产 `strict_provider` 禁止回退错误供应商。
- `build_w30_douyin.py`：运行时场景 ID 加 `content_id` 前缀，隔离并行帧目录；TTS override 强制 strict provider。
- 规范层：Stage 0、覆盖矩阵、TTS 小样、时长压力测试、机器 QC 和终片哈希失效规则成为全局要求。

## 6. 尚未完成的 P0 工程项

**逐场景增量缓存**仍需实现。缓存键至少包含：模板内容哈希、scene data、真实 duration、fps、共享 CSS/JS 哈希和渲染器版本。只重渲缓存失效场景，再重做 concat、音频和机器 QC。未实现前允许全量渲染，但不得把全量渲染当成长期方案。

## 7. 以后如何判断“慢得合理”

- 因真实证据推翻命题、独立审核发现误导、终片机器指标不合格而返工：**必要质量成本**，记录原因后继续。
- 因能力未小测、路径冲突、名义时长、重复全量渲染、审稿覆盖混乱、旧评分误用而等待：**系统缺陷**，必须修门禁或工具，不能只在复盘里提醒。

衡量效率不是“多快生成 MP4”，而是：**从已验证命题到首个 B 级终片需要多少次无效全量返工**。目标是零次。
