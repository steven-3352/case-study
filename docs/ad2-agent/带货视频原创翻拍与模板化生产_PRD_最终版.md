# PRD：CLI 对话式参考视频广告二创与模板化生产系统

> **文档状态**：最终需求版  
> **版本**：V2.1  
> **日期**：2026-08-09  
> **交互形态**：用户在 CLI 中与 LLM 对话完成物料检查、参考分析、商品替换或植入、原创翻拍、风格确认、逐镜制作、验收、模板固化与批量复用。  
> **工作名称**：`adfilm`，仅作为本文 CLI 示例名，实施时可替换。  
> **核心标准**：先过权利、合规、商品准确性硬门，再在可行候选中以最终视觉效果为第一排序因素。
> **当前 I2V 范围**：MVP 优先且默认使用 Seedance 2.0；其他视频模型和 RunningHub 工作流延后，不属于当前实现、验收或上线阻塞项。
> **配套开发卡**：本 PRD 已拆成 9 张自包含开发卡（同目录 `开发卡_00_README_子agent须知.md` 起）。子 agent / 便宜模型**只读对应那张卡即可开工**，卡里直接点名用哪个现成脚本，无需通读本 PRD 或整个项目。骨架复用 `ad-agent/conductor/`（六步流水线已跑通），底层功能复用 `src/mvstudio/`。

## 0. V1.1 审查与三档抬高

### 0.1 V1.1 的主要不足

V1.1 已覆盖原创翻拍、商品尺寸适配、风格确认和模板复用，但仍有以下 P0 缺口：

1. 没有定义 CLI 命令、自然语言对话协议和用户确认语义。
2. 没有定义可暂停、可恢复、可失效、可局部重试的任务状态机。
3. 默认原视频中存在待替换商品，缺少“原视频无商品、为商品创造广告角色”的植入分支。
4. 缺少物料预检、问题分级和替换物料后的恢复路径。
5. 失败规则只有回退，没有统一的建议包，用户仍可能陷入死局。
6. 没有明确当前 I2V 的 Seedance 2.0 能力边界、验证方法和失败降级路线。
7. 没有区分当前 Seedance MVP 与未来其他模型、RunningHub 扩展，容易扩大首版范围。
8. “吸引人”没有被拆成可审查的人性动机、创意机制和合规边界。
9. 没有成本预估、付费任务确认、幂等、取消、超时和提供方故障切换。
10. 没有足够完整的数据结构、目录、审计、端到端测试和完成定义。

### 0.2 抬高三档后的目标

| 档位 | 从什么提高到什么 |
|---|---|
| 第一档 | 从“描述制作步骤”提高到“每个节点都有输入、输出、状态、门禁和恢复语义” |
| 第二档 | 从“默认调用 Seedance”提高到“验证 Seedance 的逐镜适用性，并在 Seedance 生成、受控商品合成、3D 或真人重拍之间选择视觉最优路线” |
| 第三档 | 从“成功路径能跑”提高到“任何阻塞都有建议、降级和替代路线，并能从正确节点继续” |

V2.0 的交付对象不再是一份概念说明，而是可供产品、CLI、编排、模型适配、QA 和测试共同实现的契约。

## 1. 产品定义

用户提交：

- 一条参考视频；
- 多张目标商品图片；
- 商品特点和本条重点卖点；
- 新视频的故事、受众、风格、平台和交付要求。

系统通过 CLI 与用户对话，先检查物料和权利，再理解参考视频的内容、故事、注意力机制和广告机会。随后由系统识别并让用户确认以下两种模式之一：

1. **商品替换 `replacement`**：参考视频中已有商品，用户指定要替换的对象和范围，系统决定如何重新创作动作、构图和故事。
2. **商品植入 `integration`**：参考视频中没有目标商品，系统分析商品适合在故事中承担什么角色，提出多个不违和的植入方案，由用户确认后重新创作。

新视频从零生成、拍摄或混合制作。参考视频用于分析，不默认作为最终画面底片。首条成片通过验收后，可固化为参数化模板；后续沿用生产骨架和风格，仅替换故事与商品变量，并重新求解受影响参数。

完整闭环：

```text
CLI 建项目与对话
      ↓
物料上传、指纹与权利声明
      ↓
物料预检和可行性建议
      ↓
参考视频与商品分析
      ↓
用户确认 replacement / integration
      ↓
人性动机、原创概念和风格确认
      ↓
脚本、分镜、商品动作和逐镜路线确认
      ↓
Seedance 2.0 I2V + 受控合成逐镜制作
      ↓
生成后诊断、局部重试、合成与声音
      ↓
商品、视觉、故事、原创性、合规验收
      ↓
用户确认成片
      ↓
模板固化、变量试跑与批量复制
```

## 2. 核心目标

1. 用户只需通过 CLI 对话和文件路径即可完成整个项目，不要求理解模型参数或工作流节点。
2. 系统准确理解参考视频的内容、故事、节奏和注意力机制，同时避免直接复制受保护的具体表达。
3. 系统能够识别“替换已有商品”和“向无商品视频植入广告”两类任务，并由用户最终确认。
4. 商品在新视频中具有可信尺寸、正确身份、自然动作和明确销售作用。
5. 用户的风格描述被转译为可执行的风格画像并确认，而不是原样塞入提示词。
6. 当前阶段每个镜头优先评估 Seedance 2.0 I2V，并可结合商品原图合成、3D 或真人重拍，以视觉效果和商品保真为首要排序因素。
7. 项目随时可退出和恢复；修改上游只让真正受影响的节点失效。
8. 任一节点无法继续时，系统必须给出原因、候选方案、推荐方案、影响和恢复点。
9. 首条满意成片可固化为版本化模板，并在新变量下完成真实试跑。
10. 所有输入、决策、模型、工作流、参数、成本、版本和验收均可追溯。

## 3. 非目标与边界

- 不承诺绝对消除版权、商标、肖像或平台风险。
- 不帮助规避权利人识别、平台审核或内容指纹系统。
- 不默认直接修改无权使用的参考视频画面或声音。
- 不逐镜复刻参考视频后仅更换人物、商品或像素。
- 不承诺单张商品图可以恢复准确的全部视角。
- 不用生成文字替代必须准确的 Logo、包装文字和监管信息。
- 当前 MVP 不接入 Seedance 2.0 之外的其他 I2V 模型。
- 当前 MVP 不接入 RunningHub 工作流；只保留未来扩展所需的 provider 接口边界。
- 不承诺精确复制某部电影或在世创作者的个人风格。
- 不用色情露骨、赌博诱导、毒品美化、未成年人性化或其他违规内容换取流量。
- 不把所有失败都自动降级到低质量成片；没有可信路线时应明确建议换素材、换创意或停止。

## 4. 核心原则

### 4.1 用户决定目标，系统决定执行建议

- 用户决定换什么商品、重点卖什么、面向谁、接受什么风格和最终是否通过。
- 系统自动分析原视频、候选植入点、动作适配、制作路线和失败替代方案。
- 系统可以推荐，但不能悄悄改变商品、卖点、目标受众或用户已确认的创意。

### 4.2 保留传播功能，不复制具体表达

允许借鉴销售结构、情绪功能、信息顺序和注意力机制。人物设定、故事事件、完整句式、场景、动作、镜头、音乐和标志性组合必须重新创作。

### 4.3 视觉效果优先，但硬门优先于评分

先淘汰以下不合格路线：

- 权利或合规不通过；
- 商品身份无法保持；
- 物理动作明显不成立；
- 输出规格不满足；
- 提供方不可用或无法追溯。

在剩余候选中，以最终画面表现和观众感知为第一排序因素，而不是默认模型、最低价格或最快速度。

### 4.4 风格先解释、后确认

电影名、导演名、日式动漫、写实、vlog 等输入必须被转译为媒介、写实度、色彩、光线、构图、镜头、表演、剪辑、材质和声音。确认前不得正式制作。

### 4.5 商品物理属性优先

人物动作和构图服从商品真实尺寸、重量、材质和使用方式。不能为了套模板而缩小大商品、让两根手指捏住重物或生成不存在的商品侧面。

### 4.6 永不静默死局

任何无法继续的节点必须进入 `blocked_with_recommendations`，不能只返回错误。建议必须诚实；没有高质量路线时可以推荐换参考、换商品、换故事或终止。

### 4.7 首条先验收，模板后固化

只有首条成片和至少一组替代变量试跑均通过，模板才可进入 `validated`。

## 5. 用户物料契约

### 5.1 必需物料

#### 参考视频

- 本地文件路径或合法可访问地址；
- 最高可用画质；
- 来源和使用权利声明；
- 用户希望保留的抽象内容；
- 用户明确不希望保留的部分。

#### 商品图片

- 多张图片，至少应尽量覆盖正面、背面、左右侧面和关键细节；
- 同一 SKU、颜色和包装版本；
- 原图优先，避免截图、水印和严重压缩；
- 包装源文件、透明底图、3D 模型或转台视频为可选增强物料。

#### 商品特点文本

- 商品名称、品类、目标用户和使用场景；
- 长、宽、高、重量、材质和活动部件；
- 核心卖点；
- 本条视频必须突出的一到两个重点；
- 使用方法和不能错误演示的动作；
- 必须准确显示的 Logo、包装文字和颜色；
- 禁用表述、合规限制和卖点证据。

#### 新视频要求

- 想讲的内容和目标受众；
- 期望的商品角色：不确定、替换、自然植入或结尾推荐；
- 风格自然语言描述；
- 平台、画幅、时长、分辨率和语言；
- 真人、动画、写实、vlog 或其他媒介偏好；
- 是否允许改变参考故事、人物和场景；
- 配音、字幕、音乐和 CTA 要求；
- 单条或批量、交付时间和预算上限。

### 5.2 物料目录

新项目默认建立在用户原始物料所在目录，不使用系统临时目录保存权威产物：

## 6. 物料预检与建议

### 6.1 预检项目

| 对象 | 检查内容 |
|---|---|
| 参考视频 | 可读性、时长、分辨率、帧率、压缩、镜头结构、商品可见性、权利声明 |
| 商品图片 | 清晰度、视角覆盖、SKU 一致性、色差、水印、透明通道、包装文字可读性 |
| 商品文本 | 尺寸重量、使用方式、卖点证据、禁用表述、重点是否明确 |
| 新视频要求 | 时长与信息量、风格冲突、平台规格、预算、交付时间、媒介可行性 |
| 参考与商品匹配 | 受众、场景、故事功能、动作、尺寸和品牌调性是否可结合 |

### 6.2 问题分级

- `blocking`：权利未确认、关键文件不可读、SKU 冲突、必要信息缺失。修复前禁止继续。
- `fixable`：视角不足、故事过长、风格冲突、动作难度高。系统提出补充或调整方案。
- `advisory`：可以继续，但效果存在明确上限。用户确认风险后放行。

### 6.3 预检输出

```yaml
result: conditional_pass
blocking_issues: []
fixable_issues:
  - id: MAT-004
    issue: 缺少商品背面图
    impact: 无法可信展示超过正面 60 度的旋转
recommendations:
  - option: 补充背面图片
    expected_quality: high
    cost_impact: none
  - option: 限制商品角度在正面 30 度内
    expected_quality: medium_high
    cost_impact: low
recommended_option: 补充背面图片
resume_from: N01_material_preflight
```

## 7. 制作模式

### 7.1 模式识别

系统分析参考视频中的商品、包装、配件、竞品和普通道具，并生成带时间码的对象清单。系统只提出建议，最终由用户确认模式和范围。

### 7.2 商品替换 `replacement`

适用条件：参考视频中存在需要被目标商品取代的对象或商品角色。

流程：

1. 用户点击、选择或文字指定原商品。
2. 系统传播到全部镜头并列出关联包装、配件、桌面同款和竞品。
3. 用户确认替换范围。
4. 系统比较新旧商品的尺寸、重量、结构、用途和卖点。
5. 每镜判定：轻度合成、局部动作重建、整镜重做。
6. 保留销售功能，重新创作具体故事、动作和镜头。

用户决定“换什么”，系统建议“怎么换”。

### 7.3 商品植入 `integration`

适用条件：参考视频没有目标商品，用户希望基于其内容做广告二创。

系统必须先分析：

- 人物目标和情绪弧线；
- 故事冲突和转折；
- 商品能够解决的问题；
- 商品与受众、场景和调性的匹配度；
- 植入是否破坏原内容的观看动机。

候选子类型：

| 子类型 | 商品角色 | 特点 |
|---|---|---|
| `narrative_integration` | 商品推动剧情或解决人物问题 | 最自然，改写成本最高 |
| `scene_integration` | 商品作为环境物品并被合理使用 | 改动较小，卖点表达较弱 |
| `endorsement_endcap` | 主体内容结束后由人物明确推荐 | 信息清楚，广告感更强 |

系统至少提供两个可行方案；若只有一个可信方案，应说明为什么其他方案不成立。

### 7.4 不适合植入

出现以下情况时不得硬植入：

- 商品与故事情绪严重冲突；
- 受众与商品目标用户明显不匹配；
- 商品需要复杂说明但视频没有时间；
- 用户要求完全不改原内容，又要求完整展示多个卖点；
- 商品尺寸、动作或场景无法成立；
- 合规或权利问题不能解决。

系统必须推荐：更换参考视频、调整商品角色、减少卖点、改为结尾推荐、重新创作完整故事或停止当前路线。

## 8. 人性动机与创意机制

### 8.1 定义

用户所说的“黄赌毒”在本产品中只作为对底层注意力动机的比喻，不代表制作色情、赌博或毒品内容。系统应把它转译为合规的人性驱动力：

| 底层动机 | 合规创意表达 | 禁止滑向 |
|---|---|---|
| 吸引与欲望 | 美感、魅力、向往、自我改善、关系认同 | 露骨色情、物化、未成年人性化 |
| 不确定与奖励 | 悬念、挑战、揭晓、前后反差、可控惊喜 | 赌博诱导、虚假抽奖、沉迷机制 |
| 逃离与缓解 | 放松、解压、便利、舒适、问题被解决 | 毒品美化、危险行为鼓励 |
| 身份与归属 | 圈层语言、共同经验、品味和身份表达 | 羞辱、歧视、排斥性操控 |
| 损失与安全 | 避免麻烦、降低风险、节省时间 | 夸大恐惧、制造虚假危机 |
| 掌控与效率 | 一步完成、可预测、整理感、即时反馈 | 虚假承诺、无法证明的绝对效果 |
| 关爱与责任 | 家庭、照顾、体面、卫生、可靠 | 道德绑架和健康误导 |

### 8.2 使用规则

1. 每条视频只能选择一个主要动机和最多一个辅助动机。
2. 动机必须与目标受众、场景和商品真实卖点相连。
3. 创意方案必须写明：触发哪种动机、出现在哪个时间段、观众能观察到什么。
4. 不能用抽象词“抓人”“刺激”过门，必须描述具体钩子和画面。
5. 合规门和商品真实性门优先于流量动机。

### 8.3 人性动机输出

```yaml
primary_driver: surprise_and_reveal
secondary_driver: attraction_and_aspiration
audience_truth: 观众先因舞蹈停留，再接受人物的生活化推荐
observable_hook: 前 1 秒完成一次幅度明显的舞蹈动作，结尾音乐停顿后人物看向镜头并切换到推荐状态
product_connection: 商品不推动舞蹈剧情，因此使用明示结尾推荐，不伪造因果
prohibited_tactics:
  - 性暗示强化
  - 虚假限时
  - 无证据卖点
```

## 9. 风格理解与确认

### 9.1 自然语言输入

支持电影名、剧集名、创作者名、日式动漫、二维手绘、三维渲染、写实、纪实、广告、vlog、年代、地域、情绪、色彩、光线和相机描述。

### 9.2 风格画像

系统必须回显：

- 视觉媒介；
- 写实程度；
- 色彩和肤色；
- 光线来源、软硬和方向；
- 构图、景别和景深；
- 相机运动及可观察幅度；
- 表演自然度；
- 剪辑节奏；
- 画面材质；
- 声音距离、环境声和音乐功能；
- 明确禁止项。

采用一个主风格锚点和最多两个辅助特征。多个冲突风格不能直接堆叠。

### 9.3 命名参考转译

电影名或创作者名只用于识别用户偏好的高层视听属性，不复制具体人物、场景、服装、道具和标志性镜头。对在世创作者不承诺精确仿制个人风格，应回显不带姓名的通用特征组合。

### 9.4 确认门

用户可执行：确认、修改单个维度、重新解释、查看概念帧。只有 `style.status=approved` 后才能进入正式分镜。

模板固化后风格默认是稳定参数。改变主风格锚点、媒介或写实度时，创建模板风格分支并重新确认。

## 10. CLI 产品体验

### 10.1 CLI 入口

```bash
adfilm new --project-dir /path/to/materials
adfilm chat /path/to/materials
adfilm resume /path/to/materials
adfilm status /path/to/materials
adfilm export /path/to/materials
```

`adfilm chat` 是主要入口。其他命令用于自动化、恢复和排障，不要求普通用户记忆复杂参数。

### 10.2 对话内控制命令

| 命令 | 作用 |
|---|---|
| `/attach <type> <path>` | 添加参考视频、商品图片、商品说明或需求文件 |
| `/materials` | 查看物料清单、缺口和哈希 |
| `/status` | 查看节点进度、当前阻塞和下一步 |
| `/continue` | 从第一个合法的未完成节点继续 |
| `/approve [node]` | 确认当前拍板点 |
| `/revise <node> <instruction>` | 修改指定节点 |
| `/retry [node|shot]` | 重试失败节点或单镜 |
| `/choose <option-id>` | 选择系统建议或创意候选 |
| `/rollback <node>` | 回滚到已保存节点，不删除历史版本 |
| `/routes` | 查看逐镜 Seedance 直接生成、混合合成、3D 或真人路线及理由 |
| `/cost` | 查看已花费、预估和预算余额 |
| `/artifacts [node]` | 查看节点产物路径 |
| `/cancel [job]` | 取消尚可取消的任务 |
| `/export` | 导出成片、模板或报告 |
| `/help` | 查看当前上下文可用命令 |

自然语言和命令等价。用户说“继续”“用第二个方案”“第 3 镜重做”时，LLM 应解析为相应操作并在有歧义时确认对象。

### 10.3 LLM 回复契约

每次关键回复按以下顺序：

1. 当前结论；
2. 证据或原因；
3. 用户需要决定的唯一问题；
4. 可选项及影响；
5. 系统推荐；
6. 选择后进入哪个节点。

禁止一次抛出十几个问题。系统应优先从物料推断，只询问会实质改变结果的缺口。

### 10.4 “继续”语义

`/continue` 不等于无条件执行下一行代码。系统必须：

1. 检查项目锁和当前运行任务；
2. 重算节点依赖是否仍有效；
3. 找到第一个 `pending`、`stale`、`failed_retryable` 或已获批准可运行的节点；
4. 若下一步产生显著费用或需要用户拍板，先展示影响并等待确认；
5. 否则执行该节点并保存结果；
6. 返回新状态和下一步。

### 10.5 CLI 中断恢复

- 用户关闭终端不取消远程生成任务。
- `resume` 恢复会话上下文、任务状态和未消费结果。
- 远程任务使用幂等键，重复执行不得重复扣费或生成不可追溯副本。
- 同一项目默认只有一个写入会话；第二个会话只读或需显式接管。
- 每条对话和状态变更写入追加式事件日志。

### 10.6 组件边界

| 组件 | 职责 |
|---|---|
| CLI Shell | 参数解析、交互显示、文件路径和流式输出 |
| Conversation Orchestrator | 维护对话上下文，把自然语言转成受控意图 |
| State Machine | 验证节点转换、批准、失效和恢复；它是状态唯一写入者 |
| Material Service | 文件登记、哈希、预检和不可变原件保护 |
| Analysis Service | 参考视频、商品、故事、风格和植入机会分析 |
| Creative Planner | 人性动机、原创概念、脚本和分镜候选 |
| Provider Registry | 当前管理 Seedance 能力、版本、健康和基准；保留未来 provider 扩展接口 |
| Shot Router | 逐镜硬门、评分、路线选择和 fallback |
| Job Manager | 异步提交、轮询、取消、幂等、成本和结果归档 |
| QA Engine | 单镜和全片自动检查、独立人工验收入口 |
| Recommendation Engine | 把阻塞转换为有影响说明的可执行建议包 |
| Template Engine | 稳定参数、变量、派生规则、版本和批量试跑 |

LLM 只能提出意图、调用受控工具和解释结果，不能直接修改 `state.json`、伪造批准、跳过门禁或把生成成功当作验收通过。所有状态转换必须由 State Machine 根据当前版本和依赖执行。

### 10.7 机器可读模式与退出码

所有非聊天命令支持 `--json`，输出稳定的事件或状态对象，便于脚本和 CI 使用。聊天界面仍以自然语言为主，但每次关键动作同时保存结构化事件。

建议退出码：

| 退出码 | 含义 |
|---:|---|
| 0 | 命令成功或节点完成 |
| 2 | 正在等待用户输入或批准 |
| 3 | 阻塞，但已有建议可选择 |
| 4 | 可重试的提供方或任务错误 |
| 5 | 无法自动恢复的配置或数据错误 |
| 130 | 用户取消当前 CLI 进程；远程任务状态以 Job Manager 记录为准 |

## 12. 永不死局建议系统

### 12.1 触发条件

- 物料不完整或不一致；
- 商品无法自然替换或植入；
- 风格、时长、预算和故事冲突；
- Seedance 或合成任务生成失败；
- 单镜三次仍无法通过；
- 提供方不可用；
- 合规、权利或商品准确性无法通过；
- 模板超出适用范围。

### 12.2 建议包 Schema

```yaml
status: blocked_with_recommendations
node: N12
reason_code: PRODUCT_IDENTITY_DRIFT
plain_reason: 商品包装文字连续三次漂移
evidence:
  - qa/shot-04-attempt-3.yaml
options:
  - id: O1
    action: 改为受控商品图层合成
    expected_visual_quality: high
    product_fidelity: high
    cost_delta: medium
    time_delta: medium
    invalidates: [N11_SHOT04, N13, N14]
  - id: O2
    action: 限制商品为正面定帧展示
    expected_visual_quality: medium
    product_fidelity: high
    cost_delta: low
    time_delta: low
recommended_option: O1
recommendation_reason: 保住包装准确性的同时不降低整片视觉完成度
resume_from: N11_SHOT04
```

### 12.3 建议优先级

1. 补充或替换物料；
2. 只调整受影响变量；
3. 更换商品动作或植入方式；
4. 调整 Seedance 输入条件、镜头动作或生成策略；
5. 改为 Seedance 生成加受控商品合成、3D 或真人重拍；
6. 更换参考、模板或完整创意；
7. 保存已有产物并终止。

建议必须包含效果、商品保真、成本、时间和失效范围，不能只说“再生成一次试试”。

## 13. Seedance 优先的 I2V 架构

### 13.1 当前阶段范围

MVP 的 I2V 优先且默认使用 Seedance 2.0。当前只实现和验收一个 I2V provider，不把其他视频模型或 RunningHub 纳入首版依赖。

Seedance 并不负责所有最终像素。为保证商品准确性，当前可用路线包括：

- Seedance 2.0 直接 I2V；
- Seedance 2.0 生成人物、场景和动作，再用用户商品原图受控合成；
- Seedance 2.0 与简易 3D 商品结合；
- Seedance 无法满足时，建议改变镜头、采用传统合成或真人重拍。

视觉效果优先仍然生效，但当前比较的是上述制作路线，不是多个 I2V 模型之间的竞赛。

### 13.2 Seedance 能力清单

```yaml
provider_id: seedance-2.0
provider_type: i2v_model
platform: configured_seedance_provider
version: "doubao-seedance-2-0-260128"      # 实测跑通的模型标识；代码缺省回退 doubao-seedance-2-0
capabilities:
  tasks: [image_to_video]                   # ✅ 实测
  input_modalities: [image, video, audio]   # ✅ 实测：多模态 metadata.content[]
  supports_multi_reference: true            # ✅ 实测：2×reference_image + reference_video + reference_audio 同时传入
  supports_first_last_frame: true           # ✅ 实测：首帧=图片1、尾帧定格=图片2（reference_image role + 提示词约定）
  supports_mask_control: unknown_until_probe
  supported_durations_s: [11]               # ✅ 实测 11s；生产代码约束 4–15s（gen_video 里 max(4,min(15,dur))）
  aspect_ratios: ["16:9", "9:16"]           # ✅ 16:9 实测；9:16 由 provider/ASPECT_MAP 支持（1:1 目标按 9:16 出片再合成）
  supports_generate_audio: true             # ✅ 实测：generate_audio 可控（带 reference_audio 时自动开启）
  supports_watermark_control: true          # ✅ 实测：watermark=false 可控
  product_text_fidelity: unknown_until_probe # 仍需代表镜头基准（§14.3）确认，勿凭 curl 假设
runtime:
  async: true
  request_shape: single_post_verified       # ✅ 实测：单次 POST /v1/video/generations 返回结果；长任务轮询/回调语义仍待探测
  cancellable: unknown_until_probe
commercial:
  cost_estimator: unknown_until_probe        # 费用估算仍未验证 → 触发 §17.4 知情确认
health:
  status: probe_passed_via_curl              # 已用实测 curl 打通；正式上线仍需按 §13.3 走全门禁
benchmark:
  fixture_version: ""
  scores: {}
```

> **验证来源**：以上带 ✅ 的字段来自用户实测跑通的 `POST https://<endpoint>/v1/video/generations`（`doubao-seedance-2-0-260128`，`metadata.content[]` 含 2×`reference_image` + 1×`reference_video` + 1×`reference_audio`，`duration:11`、`ratio:16:9`、`generate_audio:true`、`watermark:false`）。未标 ✅ 的字段保持 `unknown_until_probe`，须由项目账号与代表镜头基准确认，不得凭模型名或本 curl 外推。

能力字段必须由项目实际使用的 Seedance 接口和账号验证后填写。未知字段标记为 `unknown_until_probe`，不得凭模型名称或宣传文案假设。

### 13.3 Seedance 上线门禁

1. 能完成健康检查；
2. 实际输入、输出、时长、画幅和文件规格已验证；
3. 提交、查询、取消、超时、重试和幂等语义明确；
4. 费用可估算，或在提交前明确显示无法精确估算；
5. 使用固定代表镜头完成视觉、动作、人物和商品保真基准；
6. 记录 Seedance 适合和不适合的镜头类型；
7. 至少验证一次“Seedance 生成 + 商品受控合成”的混合路线。

### 13.4 未来扩展，当前搁置

其他 I2V 模型和 RunningHub 工作流不进入当前 MVP，不要求用户现在提供账号、工作流 ID、API 文档或凭证，也不作为 P0 缺口。

核心状态机仍通过 provider adapter 调用 Seedance，避免未来扩展时重写 CLI 和任务节点。只有出现以下触发条件时，才为后续版本立项：

1. Seedance 在关键镜头上连续达到失败升级条件；
2. Seedance 的视觉上限、商品保真、成本或时延无法满足业务目标；
3. 用户明确要求接入另一个模型或 RunningHub；
4. 已有真实工作流、API 权限和可验证样片。

未来接入仍需能力探测、代表镜头基准、费用与幂等验证，但这些工作不阻塞当前 Seedance MVP。

### 13.5 参考视频运镜合规与去身份化

Seedance 2.0 多模态 `metadata.content[]` 已实测跑通，可携带 `reference_video`（运镜/动势参考）、`reference_image`（首/尾帧参考，最多 4 张）、`reference_audio`（背景音）。参考视频**只用于复制运镜与动势，不做精确骨骼编舞替换**（用户已明确接受）。为避免把受保护的具体表达（人物长相、身份、可识别画面）带进新片，参考视频进入模型前必须经过去身份化门。

**去身份化实现（复用现有能力，不另造）**：调用 `mvstudio.media.generate_pose_reference(source, out_path, min_coverage=0.65, label=True)`（`ad-agent/conductor/media.py` 已有薄封装 `pose_reference_from_video`）。它用 MediaPipe 只渲染躯干/四肢骨架（索引 11–32，**不含面部**）到纯色画布，输出只保留运动与时序、丢弃长相与身份，返回 `PoseReferenceResult(output, frames, detected, coverage, fps)`。

**合规门（先硬门、后使用）**：

1. **去身份化优先**：默认把参考视频先转成 `pose_reference` 骨架视频，再作为 `reference_video_url` 喂给 Seedance；只有当运镜信息在骨架化后不足以传达、且用户对该原视频拥有权利并显式确认时，才允许原片直传。
2. **覆盖率门**：`coverage = detected / frames` 低于 `min_coverage`（默认 0.65）时 `generate_pose_reference` 抛 `PoseReferenceError`，判定"素材缺清晰全身主体"→ 进入 §12 建议包（换参考片段 / 改镜头设计 / 放弃运镜复制），不静默降级。
3. **托管方式**：去身份化产物与参考素材以服务器 nginx 公网目录提供 https URL 直传 Seedance（provider 只接 https URL、无上传逻辑，见 §20.4）；托管细节不在本 PRD 展开。
4. **原创性判定绑定 AC-05**：运镜/节奏可借鉴，但人物、事件、台词、动作、镜头不得与参考视频连续一一映射；骨架参考天然剥离长相，进一步降低"仅换像素"的复刻风险。

验收补充：AC-11 视觉路线在使用 `reference_video` 的镜头上，须记录"原片直传 / 骨架去身份化"二选一的理由与覆盖率；未过覆盖率门的参考片段不得进入批量。

## 14. 逐镜视觉路线选择

### 14.1 先硬门、后评分

候选路线先过：权利、合规、商品身份、物理动作、输出规格和 Seedance 服务健康硬门。通过后按以下权重排序：

| 维度 | 默认权重 |
|---|---:|
| 最终视觉完成度与风格表现 | 35% |
| 商品身份和包装保真 | 20% |
| 人物、商品和背景的时间连续性 | 15% |
| 动作、受力和遮挡可信度 | 10% |
| 镜头表现力与故事服务度 | 10% |
| 可编辑、可诊断和可复现 | 5% |
| 成本和时延 | 5% |

用户可以声明预算或时限为硬约束，但不能让低成本自动覆盖商品准确性和基本视觉门。

### 14.2 逐镜而非整片锁定

同一视频可在 Seedance 优先的前提下采用：

- 人物动作由 Seedance 2.0 生成；
- 商品正面用原图或 3D 精确合成；
- 包装文字用受控图层；
- 特殊转场使用当前项目已有的剪辑或合成能力；
- 失败镜头先调整 Seedance 输入和镜头设计，仍失败则改为合成、3D 或真人重拍；
- 最终统一色彩、颗粒、声音和字幕。

### 14.3 新路线代表镜头测试

首次配置 Seedance 或改变关键生成参数时，先选择全片最具代表性且风险高的 2 至 4 秒片段生成小样。只有样片达到抬高后三档的视觉目标，才允许批量展开。

### 14.4 路由输出

```yaml
shot_id: S04
requirements:
```

## 15. 创意、脚本与分镜协议

### 15.1 原创概念候选

系统至少生成三个在故事机制上不同的概念，不允许只是换措辞。每个概念包含：

- 主要人性动机；
- 目标受众真实场景；
- 商品角色；
- 前 3 秒钩子；
- 故事转折；
- 商品出现原因；
- 视觉主场面；
- 风险和不选原因。

### 15.2 商品植入自然度

不违和必须被拆成可验证条件：

- 商品出现前有动机或明确广告状态转换；
- 商品出现位置不破坏情绪高潮；
- 人物有合理拿取、使用或推荐理由；
- 商品动作符合体积和重量；
- 商品卖点与前文或明确推荐段相连；
- 音乐、镜头和表演的转变是有意设计而非随机硬切；
- 盲测者能够理解为什么此时出现商品。

### 15.3 大白话分镜硬门

每镜必须向用户显示：

```text
【S04 · 9.5-13.0 秒】
画面：成年女舞者完成最后一个动作后看向镜头，镜头从全身切到腰部以上；右侧矮台上放着一提卫生纸。
动作：她向右走半步，双手拿起大包装，包装正面朝镜头，脸和商品同时完整可见至少 2 秒。
相机：3.5 秒内从全身切到中景，不写效果名，以人物和商品的可见变化描述。
声音：舞蹈音乐在动作结束处收住，环境声保留，人物开始推荐。
服务：从舞蹈内容明确切换到主播推荐，避免商品凭空出现。
```

用户未确认，不进入高成本制作。

## 16. 商品身份与物理适配

### 16.1 商品身份模型

记录尺寸、重量、材质、结构、活动部件、使用方法、颜色、Logo、包装文字、禁止变形区域和可接受视角。

### 16.2 尺寸与动作分档

- A 档：尺寸差较小，原动作逻辑仍成立；重新合成商品、遮挡和光影。
- B 档：人物主体可用，但需重建手指、手臂、握持或构图。
- C 档：原姿势和取景不成立；重做动作或整镜。

### 16.3 商品保真策略

- 生成模型负责人物、场景和非关键过渡；
- 商品关键表面优先使用用户原图、受控合成或 3D；
- Logo 和包装文字不能依赖逐帧生成；
- 多视角不足时限制镜头角度或要求补素材；
- 透明、高反光、柔性和液体商品单独评估。

### 16.4 关键帧生成链路（复用 ad-agent 现有能力，不另造轮子）

N10 关键帧不新写图像子系统，直接复用 `ad-agent/conductor` 已跑通的两条链路（见 `gen_keyframe`，`ad-agent/conductor/tools.py`）。逐镜按 `shot.type` 分流：

| 镜型 | 链路 | 商品保真 | 复用的现有实现 |
|---|---|---|---|
| `display`（展示镜） | AI 只画**纯背景**（提示词显式声明不含任何产品/主体）→ 产品原图按比例缩放后 PIL `paste`，像素不重绘 | **构造级 100%**：产品区 = 原始字节 | `media.compose_product_on_background(bg_bytes, product, canvas)` |
| `generated`（生成镜） | AI 直接出首帧，可选带产品参考图（`product_ref` 为真时），允许合理漂移 → cover 到画布 | 中（用于人物/场景/过渡，非关键商品面） | `provider.generate(prompt, references, size, quality)` + `media.fit_image_to_canvas(raw, canvas)` |

链路约束（均为现状，不新增）：

- 图像 provider 固定走 `OpenAICompatibleImageProvider`（`_image_provider()`，模型 `gpt-image-2`），强制 HTTPS，尺寸取 `aspect_spec(aspect)["image_size"]`（`1024x1536` / `1536x1024` / `1024x1024`）。
- 画布尺寸取 `aspect_spec(aspect)["canvas"]`；`display` 镜的产品四周留 `margin_ratio=0.12` 默认边距、居中。
- **Logo 与包装文字铁律**：关键商品面一律走 `display` 合成路径（原图 paste），不得依赖 `generated` 镜逐帧生成——与 §16.3 一致，此处给出落地绑定。
- 关键帧产物写入 `keyframes_index.yaml`，每张记 `digest = sha256_bytes(data)`，支持 `params["only"]` 单镜/子集增量重出（对应 §11.4 局部失效）。

验收补充：AC-08 商品身份的"关键商品面必须走 `display` 合成"由本链路的镜型分流保证，QA 在 N12 校验镜型与 `product_overlays` 一致。

## 17. 生成、诊断与合成

### 17.1 任务提交

提交前显示：镜头、提供方、工作流或模型版本、预计成本区间、预计时长、输入哈希和幂等键。

### 17.2 单镜诊断

每次生成后检查：

- 商品结构和文字漂移；
- 人脸、手指和身体连续性；
- 穿模、遮挡和受力；
- 风格、色温和材质一致性；
- 相机运动是否达到可观察量级；
- 黑帧、闪烁、重复帧和编码错误；
- 与分镜和人性动机的对应关系。

每次迭代只改变一到两个关键变量。连续三次救不活，必须更换路线或镜头设计。

### 17.3 合成与声音

- 统一画幅、帧率、颜色、颗粒和锐度；
- 商品精确图层和遮挡在最终合成中锁定；
- 配音必须来自确认脚本；
- 字幕烧录并遵守安全区；
- SFX 独立存在；
- 密集口播不默认叠加喧宾夺主的 BGM；
- 参考视频声音不得直接复用，除非用户拥有权利并明确要求。

### 17.4 成本触顶与预算保护

Seedance 费用可能在提交前无法精确估算（§13.2 `cost_estimator: unknown_until_probe`）。系统不得因为估不准就静默扣费，也不得因为触顶就丢弃已产出成片。

**估不准时的知情确认**：

- 单镜或批量提交前，Job Manager 显示可估区间；无法精确估算时，明确显示"无法精确估算"并给出历史同类镜的实际花费区间参考（来自 `jobs/` 的 `actual_cost` 记录），等待用户确认后才提交（对应退出码 2）。
- 确认粒度：用户可选"逐镜确认"或"整批一次确认，触顶即停"。

**批中触顶（hard_limit 命中）**：`project.yaml.budget.hard_limit` 命中时，当前进行中的镜跑完即暂停后续提交，进入 `blocked_with_recommendations`（§12），建议包至少给出：

| 选项 | 动作 |
|---|---|
| 保留继续 | 提高预算上限后从暂停镜续跑（保留已成片，不重复扣费） |
| 保留降档 | 把剩余高成本 `i2v` 镜改为本地免费路径（`static` / `ken_burns`，见 `gen_video`）后继续 |
| 保留终止 | 保存已产出镜与 `jobs/` 记录，标记项目暂停，不丢任何已扣费产物 |

**不变量**：任何触顶处理都保留幂等键与已下载产物（§10.5），暂停不取消已提交的远程任务；`/cost` 随时可查已花费、预估与余额。触顶不得触发"自动降到低质量成片"（违反 §4.6 与 §3 边界）。

## 20. 安全、合规与权利

### 20.1 权利

- 保存参考视频来源和用户权利声明；
- 保存商品图片、Logo、音乐、字体和声音的许可信息；
- 不把用户素材默认用于其他项目或训练；
- 原创性报告不等于法律意见。

### 20.2 广告和商品

- 卖点只能来自用户提供的商品资料和证据；
- 医疗、食品、化妆品、金融等敏感品类进入专项合规检查；
- 不生成绝对化、虚假限时、伪造使用结果或虚假用户证言；
- 按平台和地区要求保留广告标识。

### 20.3 人性动机边界

- 禁止色情露骨和未成年人性化；
- 禁止赌博诱导、虚假抽奖和沉迷强化；
- 禁止毒品美化或危险模仿；
- 禁止用羞辱、歧视、恐惧和健康焦虑强迫转化；
- 可以使用美感、悬念、惊喜、身份、归属、便利、关爱和损失厌恶，但必须与真实商品价值一致。

### 20.4 凭证和隐私

- Seedance 凭证进入系统密钥存储或环境引用，不写项目文件和对话日志；
- 日志中的签名 URL、令牌和个人信息必须脱敏；
- 项目之间资产隔离；
- 支持配置本地保留期限和删除策略。

## 21. 验收标准

### AC-01 CLI 完整闭环

用户能从空目录创建项目，经对话完成物料、分析、确认、制作、验收和导出；无需直接编辑内部 YAML。

### AC-02 中断恢复

在任意异步节点关闭 CLI 后重新 `resume`，项目状态、远程任务和已完成产物不丢失、不重复扣费。

### AC-03 物料门禁

缺关键物料时系统不得进入制作；问题、影响、建议和恢复节点清楚可执行。

### AC-04 模式正确

- 原视频存在商品时，系统列出对象和关联范围，用户可确认替换对象；
- 原视频无商品时，系统提出植入方案，不虚构原视频存在商品；
- 模式最终由用户确认。

### AC-05 原创性

新视频不直接复用无权使用的原画面、声音或字幕；人物、事件、台词、动作和镜头不连续一一映射参考视频。

### AC-06 人性动机有效且合规

创意说明主要动机、目标受众、可观察钩子和商品连接；不存在用露骨色情、赌博或毒品内容获取注意力。

### AC-07 风格确认

用户原始描述被转译并确认；概念帧和成片在媒介、色彩、光线、镜头、表演、剪辑、材质和声音上保持一致。

### AC-08 商品身份

商品比例、结构、颜色、Logo 和指定文字正确；不可见视角不被当作准确事实生成；连续镜头不漂移。

### AC-09 物理合理

手指接触稳定，无遮挡错误和穿模；商品尺寸和重量与人物动作、受力和构图一致。

### AC-10 植入自然度

商品出现前有合理动机或明确广告状态转换；盲测者能理解商品为什么此时出现，不认为画面是随机拼接。

### AC-11 视觉路线

每镜路线须说明选择 Seedance 直接 I2V、Seedance 加受控商品合成、3D、传统合成或真人重拍的理由和 fallback。Seedance 未经过代表镜头测试不得批量使用。

### AC-12 视觉质量

正常播放无明显闪烁、结构漂移、黑帧、重复帧、错误运动模糊或色温跳变；镜头运动达到分镜声明的可观察幅度。

### AC-13 失败建议

所有阻塞状态都返回结构化建议包，至少包含两个方案或说明为什么只有一个，且包含效果、成本、时间、失效范围和恢复点。

### AC-14 局部失效

修改单镜只重做该镜和下游合成；更换商品使商品分析后的节点失效；未受影响产物继续有效。

### AC-15 提供方故障

提供方超时或不可用时，系统不丢任务，能够重试、切换 fallback 或返回建议，且保留成本和错误记录。

### AC-16 模板复用

至少一组新变量无需重做整个流程即可生成；超出适用范围时模板能正确拒绝并建议分支或新建模板。

### AC-17 可追溯

任何成片均可追溯到参考分析、商品物料、脚本、风格、分镜、逐镜路线、Seedance 版本、生成参数、成本、人工修改和批准记录。

## 22. 示例：美女跳舞 + 一提卫生纸

### 22.1 系统判断

- 原视频没有目标商品；
- 舞蹈与卫生纸缺少自然因果；
- 用户明确要求结尾由美女推荐；
- 推荐模式：`integration`；
- 推荐子类型：`endorsement_endcap`；
- 人性动机：前段用美感和节奏吸引，后段用状态切换和轻微反差完成推荐；
- 不建议强行用卫生纸推动舞蹈剧情。

### 22.2 推荐时间线

| 时间 | 内容 |
|---:|---|
| 0-2 秒 | 成年女舞者用新的舞蹈动作进入画面，形成停留钩子 |
| 2-8 秒 | 重新编排舞蹈和镜头，保留能量而不复制原编舞 |
| 8-9.5 秒 | 音乐完成收尾，人物定住并看向镜头 |
| 9.5-11 秒 | 镜头转中景，人物从侧边矮台拿起一提卫生纸 |
| 11-13.5 秒 | 人脸和包装正面同时可见，口播用户提供的核心卖点 |
| 13.5-15 秒 | 商品近景、真实包装文字和合规 CTA |

## 23. 非功能需求

### 23.1 可靠性

- 状态写入原子化；
- 远程任务幂等；
- CLI 崩溃后可恢复；
- 提供方结果先校验再进入资产库；
- 失败任务与成功任务隔离。

### 23.2 性能

- 普通状态查询在本地完成；
- 长任务异步执行并可观察；
- 不重复上传相同哈希的素材；
- 未受影响镜头缓存复用。

### 23.3 可观测性

记录节点耗时、排队时间、生成时间、重试次数、提供方错误、成本、QA 结果和用户批准。日志不得泄漏密钥。

### 23.4 可扩展性

新增模型或工作流通过适配器和能力清单注册，不修改核心状态机；路由器只依赖统一能力和基准结果。

### 23.5 可迁移性

项目目录包含复现所需的非敏感清单和产物；更换机器或 CLI 版本时可运行迁移检查，不把绝对临时路径写成唯一引用。

## 24. MVP 范围

### 24.1 MVP 必做

1. CLI 新建、对话、状态、继续、确认、重试和导出。
2. 本地参考视频、多张商品图片和文本 brief 输入。
3. 物料预检和三级问题报告。
4. replacement 与 integration 双模式确认。
5. integration 支持 `endorsement_endcap` 和一种叙事植入。
6. 人性动机和原创概念候选。
7. 风格转译、确认和概念帧。
8. 大白话分镜硬门。
9. 一个经过真实能力验证的 Seedance 2.0 I2V 适配器。
10. Seedance 直接 I2V、Seedance 加商品受控合成等逐镜路线和 fallback。
11. Seedance 代表镜头测试。
12. 异步任务、退出恢复、幂等和成本记录。
13. 商品原图受控合成，保护包装文字。
14. 单镜 QA、三次失败换路线和最终 QA。
15. `blocked_with_recommendations` 建议包。
16. 首条模板固化和一组变量试跑。

### 24.2 MVP 暂不做

- Seedance 2.0 之外的其他 I2V 模型；
- RunningHub 及其他工作流平台接入；
- 多用户协同编辑和细粒度权限；
- 自动发布到平台；
- 所有敏感商品品类的完整法律规则库；
- 复杂透明、液体、柔性和镜面商品的全自动处理；
- 无人工确认的全自动批量外发。

## 25. 实施前 Spike

1. 获取当前 Seedance 2.0 接口、账号权限和实际模型标识。
2. 验证提交、状态查询、结果下载、取消、超时、费用和幂等能力。
3. 用固定代表镜头验证 Seedance 的人物、动作、风格、相机和时间连续性上限。
4. 比较 Seedance 直接 I2V 与 Seedance 加商品受控合成的商品保真和最终视觉效果。
5. 验证商品原图或 3D 精确合成能否与 Seedance 视频稳定结合。
6. 验证 CLI 中断时 Seedance 远程任务不会丢失或重复提交。
7. 用“美女跳舞 + 一提卫生纸”跑通 integration/endcap 全链路。
8. 用“原视频已有小商品 + 更大商品”跑通 replacement 全链路。

## 26. 成功指标

### 产品指标

- 首次预检能发现关键物料缺口的比例；
- 用户在关键帧阶段而非成片阶段发现方向错误的比例；
- 中断后成功恢复率；
- 单镜局部重试率和整片无谓重跑率；
- 阻塞建议被用户采用后成功继续的比例；
- 模板变量试跑通过率。

### 质量指标

- 商品身份和包装准确通过率；
- 手部、受力和遮挡通过率；
- 风格一致性通过率；
- 植入自然度盲测通过率；
- 原创性独立复核通过率；
- 用户首条成片批准轮次；
- Seedance 直接 I2V 与混合合成路线的视觉和商品保真通过率。

不能用“任务提交成功”或“生成了 mp4”作为产品成功指标。

## 27. 最终完成定义

系统只有在以下条件同时满足时才算完成：

1. 用户可通过 CLI 对话完成全流程，无需直接操作模型或工作流 UI；
2. 物料、权利、商品和新视频要求经过预检；
3. 系统正确识别并由用户确认 replacement 或 integration；
4. 原创概念明确使用合规的人性动机，而非字面色情、赌博或毒品刺激；
5. 风格经过解释、概念验证和用户确认；
6. 当前 I2V 优先使用 Seedance 2.0，并按镜头在 Seedance 直接生成、受控商品合成、3D 或真人重拍之间选择视觉和商品保真更高的路线；
7. 其他视频模型和 RunningHub 未进入当前实现、验收或上线阻塞项；
8. 指定商品以可信尺寸、正确身份和自然交互进入新故事；
9. 任一失败都有结构化建议和明确恢复点，不存在无解释死局；
10. 项目可以退出、恢复、局部失效、局部重试并避免重复扣费；
11. 首条成片通过商品、视觉、原创、合规、声音和用户验收；
12. 首条成片可固化为模板，并由至少一组新变量验证；
13. 所有输入、决策、Seedance 版本、参数、成本、产物和批准记录可追溯。

## 28. 测试夹具与回归矩阵（工程附录）

测试复用现有工程基座，不另建测试框架。pytest 为唯一框架；解释器 `.venv/bin/python`，导入以 `PYTHONPATH=src` 为前缀。

### 28.1 复用的现有夹具与模式

| 复用对象 | 位置 | 用途 |
|---|---|---|
| Seedance provider 契约测试 | `tests/mvstudio/providers/test_seedance.py` | 断言 body 契约、`metadata.content[]` 加法式结构、参考 URL 安全校验（HTTPS 强制、拒绝凭据/query/fragment）、transport error 脱敏 |
| 帧摘要工具 | `tests/support/frame_digest.py` | 生成/比对确定性帧指纹，作视觉回归基线 |
| E2E 模式 | `tests/e2e/` | 六步链路 00→05 的贯通样例 |

新增测试**沿用**上述断言风格：provider 层用 fake transport 断言请求体（不打真接口），媒体变换层用固定输入字节断言 `sha256_bytes` 摘要（`compose_product_on_background` / `fit_image_to_canvas` 产物应字节可复现）。

### 28.2 夹具版本化

- 参考素材与期望产物以 `fixture_version` 标记（对应 §13.2 `benchmark.fixture_version`）；Seedance 模型标识或关键生成参数变更时递增版本，旧版本基线保留不覆盖。
- 代表镜头小样（§14.3）的期望帧指纹随 `fixture_version` 归档，作为"抬高三档"视觉门的回归锚点。

### 28.3 回归矩阵（最小集）

| 维度 | 用例 |
|---|---|
| 镜型分流 | `display` 走 `compose_product_on_background`（产品区字节 = 原图）；`generated` 走 `fit_image_to_canvas` |
| Seedance 契约 | 无参考 URL → 不追加 `content[]`、`generate_audio` 保持关；带 `reference_video/audio/image_urls` → `content[]` 顺序与实测 curl 一致、有 audio 时自动开 `generate_audio` |
| 参考 URL 安全 | 非 https（非 loopback）被拒；含凭据/query/fragment 被拒 |
| 去身份化门 | `generate_pose_reference` 覆盖率低于 `min_coverage` 抛 `PoseReferenceError` |
| 本地免费路径 | `static` / `ken_burns` 镜不初始化 Seedance、不扣费 |
| 局部失效 | `params["only"]` 单镜重出只改目标镜、增量合并 index |
| 幂等 | 同 `idempotency_key` 重复提交不重复扣费、不产出不可追溯副本 |

```bash
PYTHONPATH=src .venv/bin/python -m pytest tests/mvstudio/providers/test_seedance.py -q
PYTHONPATH=src .venv/bin/python -m pytest --cov=src --cov-report=term-missing
```
