## Q4 · 数据怎么用

**结论：** 有真实用真实；没有允许叙事修饰，但有底线。

| 层级 | 来源 | 用法 |
|------|------|------|
| **A 真实** | 真实私信、真实后台、真实录屏 | 优先使用，可打码 |
| **B 项目真实+效果区间** | 系统确有其物，效果用区间/趋势 | 「留资个位数」「曝光几百」 |
| **C 叙事修饰** | 无数据时的合理表述 | 禁止 P 图假后台、禁止可验证的假里程碑 |

项目本身（页面、邮件、表单）**必须真实**；效果数字可以区间化或叙事化。

## Q9 · 视觉路线（去 AI 味 / 去模版化）

**结论（2026-06-16）：** 选 **路线 1 · 证据优先**。不出镜；**不用 AI 生图做主视觉**；画面以脏真实截图、真备忘录、手写标注为主。

### 做什么

| 原则 | 说明 |
|------|------|
| **证据优先** | 80% 画面 = 真实截屏/录屏帧，保留 URL 栏、状态栏、时间戳等使用痕迹 |
| **体裁混搭** | 同一套图文 ≥3 种体裁（备忘录 / 浏览器 / 收件箱 / 后台 / 标注对比），禁止 7 张同一 HTML 模版 |
| **标注痕迹** | 红圈、箭头、高亮用「系统 markup / 手写」风格，不用设计软件精致排版 |
| **AI 图** | 本路线 **不用**；若日后混用，仅作 ≤2s 转场空镜，且不得含可读中文 |

### 禁止什么

- `build_slides.py` 黑金架构 slide **直出**（含「数据闭环」「全链路漏斗」「AI 服务商」那套）
- `build_shots.py` 精美包装帧 **当主视觉**（可作素材库，发布须用 raw 截屏或裁切局部）
- Chrome 渲染的统一「备忘录风」HTML 模版批量出图
- 每张相同结构：页眉「真实项目 · P001」+ 大标题 + 页脚「项目实拍」

### 视频（同路线）

优先级：**录屏快切** > **标注截图** > 静态设计帧。禁止整段停一张 slide + 底部字幕条。

### 禁霓虹色细则（2026-06-27 W27D04 教训补充）

**起因：** W27D04 抖音封面用了 `linear-gradient(135deg,#2a0e0e,#0a0e14)` 暗紫红→深蓝黑渐变 + `--red:#ff5252` 偏粉红，被识别为「AI 味」直接退稿。根因：`pipeline/p004_video/shared/style.css` 沿用了 Dracula 主题霓虹色板（开发者圈/AI 圈最套路的冷调）。

**禁止 hex/token（主视觉、封面、大字、强调色）：**

| 类别 | 禁用 | 改用 |
|---|---|---|
| Dracula 紫 | `#bd93f9` / `var(--purple)` | — 不替代,直接删 |
| Dracula 粉 | `#ff79c6` / `var(--pink)` | — 不替代,直接删 |
| Dracula 青 | `#8be9fd` / `var(--blue)` | 真截屏的系统蓝(iOS/微信原色),不要新造蓝 token |
| 暖红→冷蓝渐变 | `linear-gradient(*,#2a0e0e,#0a0e14)` 一类 | 纯黑 `#000` 或 `#0a0e14` 单色 |
| 偏粉红 | `#ff5252` / `#ff7e7e` | 血红 `#e53935` / `#c0392b` |

**允许：** 真截屏自带的系统色（iOS 蓝、微信绿 #95ec69、淘宝橙等）—— 这是真实痕迹,不是色板。

**自检：** 任何主视觉出图前，渲一帧 → grep 像素 → 若主体色落在 H=240~290（蓝紫区间）且非真截屏来源，重做。

## Q10 · 开放选题 · 选题定皮肤（2026-07-04）

**结论：** **取消固定内容皮肤**（原「小老板烦事 → 能跑的小系统」）。**受众开放** 到「任何对 AI 工具/AI 应用感兴趣的人」。**每条选题声明自己的临时皮肤**，皮肤不跨条继承。

### 为什么改

历史皮肤把系统窄化到「实体店老板 + 小系统改造」单一垂直，导致：
- 选题池变窄（只能挑「小老板烦事」类）
- 视觉/话术模板化（工种在同一皮肤下反复复用同类表达）
- 阻碍尝试非案例形态（工具评测、方法论、观察、AI 新品拆解等）

开放选题后，同一套引擎（选题→工种→pipeline→发布→复盘）可承载任意 AI 主题；每条内容对**自己的目标受众**负责，而不是对固定人群负责。

### 什么变了

| 项 | 变更 |
|---|---|
| 受众 | 「实体店老板」→ **对 AI 工具/AI 应用感兴趣的任意人群**（每条选题自定） |
| 皮肤锁定 | 全项目单一皮肤 → **每条选题在 `topic_brief.skin` 段独立声明** |
| 一句话人设 | 固定为「AI 把小老板烦事做成小系统」→ **每条选题自定人设锚**；`persona.yaml` 仅作默认参考 |
| 选题池 | 只挑「小老板」题 → **开放**：真实项目案例 / 工具评测 / 方法论 / 观察 / 新品拆解 / 带货均可 |
| 转化 | **不变**：仍是等私信（Q3） |
| 数据规范 | **不变**：仍走 Q4 三档 A/B/C |
| KPI | **不变**：仍无硬性 KPI（Q6） |
| 视觉路线 | **不变**：仍走 Q9 证据优先、禁霓虹色、禁 AI 味 |
| 工种流程 | **不变**：17 步、两道门、双人 90 分互评、fail-closed |
| 出镜 | **不变**：按形态（Q8 更新版） |

### 皮肤声明规则（每条选题必写）

在 `insights/topic_brief.md` 顶部的 `skin:` 段声明：

```yaml
skin:
  audience:          # 本条服务谁（尽量具体：X 类人 + X 场景，不写"泛 AI 爱好者"）
  persona_anchor:    # 这条我是谁（"做过 20 年互联网自己创业"，还是"刚试用某工具的普通人"）
  tone_direction:    # 口吻方向（克制/热血/自嘲/学术/评测），关键词、禁词
  hook_scene:        # 本条钉子场景（一句话可视化）
  landing_intent:    # 转化落点（私信聊 X / 主页看 Y / 纯讨论）
  format_leaning:    # 建议形态倾向（案例/评测/方法论/观察/带货），仅倾向不锁死
```

### 皮肤边界（防拧巴）

- **不得跨条继承**：D07 的皮肤不许 D08 直接套；每条重新写 `skin:`
- **不得混合皮肤**：一条内容不同时服务两批目标受众；如果两批都想服务，拆成两条
- **可以复用「判断结构」**：如「audience→hook_scene→landing_intent」这套字段是模板；但字段里填的**具体内容**必须本条重写
- **持续合法**：Q3 转化（等私信）· Q4 数据（A/B/C）· Q9 视觉路线（禁霓虹/禁 AI 味/证据优先）· 出镜 Q8 —— 与皮肤无关，**始终生效**
- **不得用皮肤绕合规**：带货选题的皮肤仍走合规工种（`CLAUDE.md` 带货 4 工种）

### 工种流程增补

- **选题深挖师** 新职责：在 `topic_brief.md` 首段写 `skin:` 声明（不写则洞察包不能定稿）
- **编导** 立项时确认 `skin:` 内部一致（audience 与 hook_scene 是否匹配、landing_intent 是否可承接）
- **视觉语言策展师 / 形式策略官** 按本条 `skin.tone_direction` 决定视觉与形式方向，不套上一条
- **运营/增长** 三平台文案按本条 `skin.audience` 与 `skin.landing_intent` 写，不套用旧文案

## Q11 · 动画导演 Motion Planner 单跑不双评（2026-07-04）

**背景：** 2026-07-04 W28D02 制作过程中，观察 3 个参考视频（WaytoAGI 信息图 / 七七 AI 插画 / 浙大猫学长 Vibe Motion）后，用户提出："补充下我们对应的岗位，这部分岗位不用再做双 agent 相互打分了。"

参考文档：
- `~/Downloads/动画分镜与vibe-motion工作流总结.md`
- `~/Downloads/两个视频动画设计与实现分析.md`

### 决定

在 **表达/音画层** 新增岗位「**动画导演 / Motion Planner**」，规则：

1. **岗位职责**：把已定的**脚本 + 留存节拍**翻译成**逐秒画面**，回答"这句话应该被看见成什么？"
2. **输出文件**：`design/motion_storyboard.md`（模板见 `templates/design/motion_storyboard.md`）
3. **输出内容**：
   - 风格判定（WaytoAGI / 七七 / Vibe Motion / 混合，4 选 1）
   - 9 字段逐秒分镜表（时间 / 旁白 / 内容类型 / 画面主体 / 动画动作 / 镜头运动 / 屏幕文字 / 素材需求 / 推荐实现方式 / 设计目的）
   - 铁律：每 2-4 秒必须有明确视觉变化
4. **单跑不双评**：本岗**不做**双 agent 90 分互评。理由：
   - 本岗是"翻译层"，不新增卖点、不改叙事结构、不改节拍
   - 下游三道门（形式策略官 form_competition / 动效技术导演 motion_tech_plan / 声音设计师 audio_plan）足以拦截
   - 打分成本 > 价值：9 字段偏工艺判断，双评往往退化成"改用词"
5. **门禁**：视频形态若无 `motion_storyboard.md`（含风格判定 + 逐秒分镜）→ **禁止**进入形式策略会（§7）
