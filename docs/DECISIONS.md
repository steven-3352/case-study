# 辩论结论 · 已锁定（执行依据）

> 日期：2026-06-16 · 后续改动需重新讨论并更新本文

## Q1 · 客户从哪来

**结论：** 目前没有付费客户。用**自己做的真实项目**引发共鸣，等对方主动私信沟通。

- 内容里的「项目」= 自己交付/搭建的系统（如现有海外品牌自动化案例）
- 不虚构客户身份，可半匿名（不出现真实品牌名）
- 未来有新项目，按同样流程追加选题

## Q2 · 内容主题

**结论：** 所有内容围绕**具体项目的制作过程、效果、讨论点**。

每条必须包含：
1. 什么麻烦 / 什么项目
2. 怎么做的（有画面）
3. 效果怎样（见 Q4 数据规范）
4. 引发讨论的问题（评论区）

## Q3 · 转化方式

**结论：** **等私信**。正文/视频不导流、不写「私信我」。

| 做 | 不做 |
|----|------|
| 主页简介说明能做什么 | 正文里写私信/扣1/加微信 |
| 评论区自然回复 | 硬广 CTA |
| 有私信后截图留存（真实素材） | 主动私信陌生人 |

详见 [CONVERSION.md](CONVERSION.md)

## Q4 · 数据怎么用

**结论：** 有真实用真实；没有允许叙事修饰，但有底线。

| 层级 | 来源 | 用法 |
|------|------|------|
| **A 真实** | 真实私信、真实后台、真实录屏 | 优先使用，可打码 |
| **B 项目真实+效果区间** | 系统确有其物，效果用区间/趋势 | 「留资个位数」「曝光几百」 |
| **C 叙事修饰** | 无数据时的合理表述 | 禁止 P 图假后台、禁止可验证的假里程碑 |

项目本身（页面、邮件、表单）**必须真实**；效果数字可以区间化或叙事化。

## Q5 · 第一期做什么

**结论：** **继续用现有自动化获客案例（Project-001）** 打磨全流程，同一项目出**多种内容形态**，发布看效果，再总结。

```
Project-001（海外品牌自动化获客）
  ├── 形态 A · 故事踩坑（图文）
  ├── 形态 B · 干货拆解（图文）
  ├── 形态 C · 成长视频（竖屏）
  └── 形态 D · ……按 pipeline 扩展
```

Phase 0 重点：数字人、配音、B-roll、剪辑 SOP
Phase 1 重点：多形态发布 → 对比数据 → 总结 win 形态

## Q6 · 成功标准

**结论：** **无硬性 KPI**。尽力做好内容，记录数据，凭感觉+数据趋势调整方向。

- `ops/rules.yaml` 里的阈值 = **参考信号**，不是过关门槛
- 不追求曝光 500、不涨粉也不焦虑
- 有私信 = 最强正向信号，记入 metrics.notes

## Q7 · 声音方案

**结论：** **放弃自研声音克隆**（GPT-SoVITS 零样本实测效果差）。

| 方案 | 状态 |
|------|------|
| GPT-SoVITS / 本地克隆 | ❌ 归档至 `legacy/voice-clone/` |
| Edge TTS（`pipeline/tts/gen_speech.py`） | ✅ Phase 0–1 默认口播 |
| 数字人 SaaS 原生音色 | ✅ 若试播满意可替代 Edge TTS |
| 剪映内置音色 | ✅ 手工兜底 |

干音资产（`assets/avatar/dry_audio/`）保留，仅供数字人 SaaS 上传或日后重试微调，不作当前 pipeline 依赖。

## Q8 · 视频画面布局

**结论（2026-06-16 更新）：** **全屏项目演示** + **Edge TTS 口播** + **字幕**；**暂停数字人**，**禁止真人/数字人任何出镜**（含右下角小窗）。

**硬约束（三平台统一，不可改）：** 图文与视频画布均为 **9:16 = 1080×1920**。禁止 3:4、iPhone 全屏比例（如 1206×2622）、禁止 16:9 横屏。常量见 `pipeline/screen_dims.py` 的 `CANVAS_W` / `CANVAS_H`。

| 层 | 内容 |
|----|------|
| **比例** | **9:16（1080×1920）** 图文 + 视频 |
| **画面** | 录屏、后台数据、系统页面、真实截图；图文满铺，视频字幕叠底部渐变 |
| **声音** | `pipeline/tts/gen_speech.py` |
| **字幕** | 必须，放底部黑边区，不压画面主体 |
| **人物** | ❌ 不做（数字人暂缓，真人自拍也不入镜） |

数字人相关资产（`assets/avatar/`）保留备查，恢复时再启用。

## Q9 · 视觉路线（去 AI 味 / 去模版化）

**结论（2026-06-16）：** 选 **路线 1 · 证据优先**。不出镜；**不用 AI 生图做主视觉**；画面以脏真实截图、真备忘录、手写标注为主。

### 做什么

| 原则 | 说明 |
|------|------|
| **证据优先** | 80% 画面 = 真实截屏/录屏帧，保留 URL 栏、状态栏、时间戳等使用痕迹 |
| **体裁混搭** | 同一套图文 ≥3 种体裁（备忘录 / 浏览器 / 收件箱 / 后台 / 标注对比），禁止 7 张同一 HTML 模版 |
| **标注痕迹** | 红圈、箭头、高亮用「系统 markup / 手写」风格，不用设计软件精致排版 |
| **AI 图** | 本路线 **不用**；若日后混用，仅作 ≤2s 转场空镜，且不得含可读中文 |

### 禁止什么

- `build_slides.py` 黑金架构 slide **直出**（含「数据闭环」「全链路漏斗」「AI 服务商」那套）
- `build_shots.py` 精美包装帧 **当主视觉**（可作素材库，发布须用 raw 截屏或裁切局部）
- Chrome 渲染的统一「备忘录风」HTML 模版批量出图
- 每张相同结构：页眉「真实项目 · P001」+ 大标题 + 页脚「项目实拍」

### 视频（同路线）

优先级：**录屏快切** > **标注截图** > 静态设计帧。禁止整段停一张 slide + 底部字幕条。

### 素材来源

| 情况 | 做法 |
|------|------|
| 有实拍 | 优先用 `assets/broll/screenshot/` 真截屏 |
| **无补拍** | `python3 pipeline/gen_evidence.py` 生成高保真仿真体裁 → `assets/broll/generated/` |

仿真仍遵守路线 1：**体裁混搭、禁黑金 slide、禁统一页眉页脚模版**。数字为 B 级叙事区间（见 Q4），非可验证假里程碑。

**布局与复盘经验** → [LESSONS.md](LESSONS.md)（含每日数据反馈模板、`ops/metrics.csv` 落地流程）。
