## 1. 核心判据(D13):什么进"列",什么进"JSON"

- **进真实列(通用骨架)**:要**查询 / 过滤 / 排序 / 关联 / 索引 / 外键 / 统计**的字段。
- **进 JSON(私有)**:只**随记录存取、不单独查**的业务私有数据。
- **兜底**:某 JSON 字段以后变"热"要查 → MySQL 用 **generated column + 函数索引**"提列",不返工。
- **纪律**:JSON 的 schema 由积木/配方契约定义、登记在 `registry`,应用层(D5)入库前校验;MySQL 不强制。**数据在 JSON 里,但它长什么样在 registry 一查就知道。**

## 2. 表清单(9 张 · 草案)

> 每张 = 通用骨架列 + 单个 JSON 私有列。加新业务/新配方**不建新表**。

### 2.1 `registry` — 注册表(D2 上帝视角)

| 列 | 类型 | 说明 |
|---|---|---|
| id | PK | |
| kind | enum | **`page` / `api` / `block` / `recipe`**(一张表四用) |
| name | str | 唯一名(同 kind 内) |
| sub_project | str | 归属子项目;通用件为 `*` |
| version | int | |
| enabled | bool | |
| spec | **JSON** | 配方 YAML / 积木契约 / 页面入口 / API 入口定义 |

> D2 的"打开库看清系统":`SELECT kind,name,sub_project FROM registry` 一览无余。

### 2.2 `project` — 业务实例(所有业务共用一张)

| 列 | 类型 | 说明 |
|---|---|---|
| id | PK | |
| tenant_id | FK | 租户隔离(D3) |
| sub_project | str | 视频 / 漫剧 / …(切几个子项目都不多建表) |
| recipe_id | FK→registry | 用哪份配方 |
| status | enum | active / expired / deleted(生命周期,D18) |
| created_at | ts | |
| expire_at | ts | **默认 created_at + 2 个月,项目级可配**(D18);GC 扫它清理 |
| data | **JSON** | 私有业务数据:商品/卖点/转化(带货)、歌曲/卡点(mv)、剧集(漫剧);保留时长等项目配置也放这 |

### 2.3 `node_state` — 状态机 / 级联(D9)

| 列 | 类型 | 说明 |
|---|---|---|
| id | PK | |
| project_id | FK | |
| node_id | str | 配方步骤 id |
| status | enum | PENDING/RUNNING/AWAITING/DONE/REJECTED |
| input_hash | str | 变化触发下游 stale(级联失效) |
| meta | **JSON** | 拍板意见等(**产物不再放这**,统一进 `artifact` 表,D18) |

### 2.4 `job` — 成本账本(D10)

| 列 | 类型 | 说明 |

| meta | **JSON** | 脱敏参数等(不存密钥/签名 URL) |

### 2.5 `event` — 事件日志(D8 · 追加式)

| 列 | 类型 | 说明 |
|---|---|---|
| id | PK | |
| project_id | FK | |
| ts | ts | |
| kind | str | 对话 / 状态变更 / 拍板 … |
| payload | **JSON** | 事件体 |

### 2.6 `asset` — 共享资产库(漫剧人设等 · **持久**)

| 列 | 类型 | 说明 |
|---|---|---|
| id | PK | |
| sub_project | str | |
| kind | str | character / style / prop / scene |
| name | str | |
| ref_key | str | `asset://` 解析键(如 `character/女主-001`) |
| data | **JSON** | 人设/画风定义、参考图指针 |

> **⚠️ 与 `artifact` 分清(D18)**:`asset` 跨项目复用、**持久**,**绝不随项目过期被清理**(别的项目还在引用)。中间产物走 `artifact`。

### 2.7 `artifact` — 中间产物(项目步骤产物 · **易逝**,D18)

| 列 | 类型 | 说明 |
|---|---|---|
| id | PK | |
| project_id | FK | **按项目清理靠它**;项目过期一把删 |
| node_id | str | 哪个步骤(配方步骤 id) |
| kind | str | image / video / audio |
| address | str | 存储地址(oss:// 或路径);GC 删行时**必须配对删此文件** |
| status | enum | candidate / selected / discarded / expired(一步多产物,选中=selected) |
| created_at | ts | |
| expire_at | ts | 随项目生命周期 |
| meta | **JSON** | 尺寸/时长/provider/参数指纹 |

> **一步多产物** = 同 `(project_id, node_id)` 多行。`node_state` 不再存产物指针,产物统一查此表。
> **GC 硬约束**:清理必须 **MySQL 行 + 存储文件配对删**,否则孤儿文件堆积 / dangling 指针。清理机制归引擎/基础设施(D8),保留时长来自 `project` 配置(默认 2 月)。

### 2.8 `membership` — 身份→租户→权限(D3 · D15 一人一租户)

| 列 | 类型 | 说明 |
|---|---|---|
| user_id | str **UNIQUE** | Supabase 身份(身份源在 Supabase,这里存映射);D15 一人一租户 → 唯一 |
| tenant_id | FK→tenant | 该用户所属租户(唯一,免租户切换器) |
| role | str | |
| perms | **JSON** | 细粒度权限 |

### 2.9 `tenant` — 租户本体(D15)

| 列 | 类型 | 说明 |
|---|---|---|
| id | PK | 被 `membership` / `project` 引用 |
| name | str | 租户名 |
| enabled | bool | |
| config | **JSON** | 租户级配置:`hard_limit`/套餐/额度(D10 触顶读这)、默认参数等 |

> **隔离强制(D15)**:MySQL 无行级安全 → 所有对 `project`/`node_state`/`job`/`event`/`asset` 的查询走**统一数据访问层**,`tenant_id` 从请求上下文自动注入。引擎不知租户:只认 `project_id`,租户经 `project.tenant_id` 派生。
