## 0. 本趟范围与原则(owner 已锁)

### 范围锁定(第一趟)

- **只做两层**:**底层基础(层1)+ 引擎(层2)+ `base/contracts`**。
- 能力积木(层3)、配方(数据)、API、前端 —— **下一趟**。**从低往上,慢慢累加。**
- 理由:积木的 I/O 契约依赖 owner 尚未重梳的业务/配方;先把两层零业务的地基砌死。

### 原则(均 owner 拍板 · 2026-08-11)

| # | 原则 | 含义 |
|---|---|---|
| P1 | **逻辑迁移 + 结构重立** | 趟过坑的**实现照搬**(不重新发明);**目录/边界/签名重立**(不继承旧摆法)。"束缚"指旧组织结构,不指旧可信逻辑。 |
| P2 | **原子性:同一功能只留一个** | 现存重复实现(ffprobe 时长、concat、hash、画幅…)**合并成唯一一份**。 |
| P3 | **无灰色地带** | 每块只归一层,归属能用总纲"三把尺子"一句话判定。 |
| P4 | **自足也要重构** | `engines/mv` 虽自足,**不因自足就整包搬**;抽其底层原子能力并入层1、同一功能一本化。 |
| P5 | **B 栈(`pipeline/*.py`)不纳** | 参 D16 式忽略:与 A 栈做同一批事却另写、重复重;其独有能力将来按需单独收编,不整体抬入。 |
| P6 | **旧四栈保留** | `ad-agent/ad2-agent/mv-agent/src` 原样留作**原子逻辑参照**,不删;业务逻辑 owner 自己重梳。 |

### 「底层基础」定义(owner 定 · 关键)

> **底层基础 = 实现功能能力,不掺杂任何业务逻辑。**

比总纲 §3.2 字面("纯生成原子:文生视频/图生视频/出图")**更宽**:不止"生成",而是**一切与业务无关的能力实现**(含 ffmpeg 拼接、PIL 贴图、画幅映射、hash、pose 抽取)。
**→ 后果**:原先设想的独立 `util/` 层取消——那些"功能能力不掺业务"的工具,本身就是底层基础。少一层 = 少一处灰带。

### 目标文件夹

- 新建 **`tonbirds-studio/`**,与旧四栈(`ad-agent` 等)**平级**,在仓库根。
- 旧四栈只作参照(P6)。本趟只往 `tonbirds-studio/` 写。

## 2. 层2 · 引擎清单

> 实测:三条 conductor 的 `state/contracts/layout/render` **ad 与 mv 逐字节相同**,`conductor.py` 仅差 26 行。引擎其实已写好,只是被复制三份 + ad2 独有两件套错层。

| 目标模块 | 引擎机制 | 迁移来源(多份→一份) | 对应决策 |
|---|---|---|---|
| `engine/contracts` | StepSpec/ToolResult/Unit/状态常量 | 三份相同 → 一份 | D4/D20 |
| `engine/state` | 状态机 + hash + 级联失效 | ad/mv 同;**ad2 是超集(385行)** → 取 ad2 版 | D9 |
| `engine/loop` | 编排主循环(选步→备输入→调积木→落产物→拍板) | `conductor.py`(26行差) → 一份 | D8/D9/D21 |
| `engine/scaffold` | 文件夹骨架/`_input`/日志/prompt 留档 | `layout.py`(三份相同) | — |
| `engine/transparency` | 跑前·跑后透明化文本 | `render.py`(三份相同) | — |
| `engine/cost` | 幂等键+成本账本+触顶暂停 | **ad2 独有** `conductor/jobs.py` → 上提 | **D10** |
| `engine/recommendations` | 建议包/永不死局 schema+校验+原子写 | **ad2 独有** `conductor/recommendations.py` → 上提 | **D11** |

> **重点**:D10/D11 总纲列为"引擎强制护栏",ad2 已原型实现且**完全业务无关**,只是锁在单 agent 里。上提即成引擎公共件。
