**设计模式（2026-07-27 从 paperdoll-mv-packaging skill 提炼 · 跨 skill 可复用）**

### 核心机关

对话不是随便聊，是**逐格填一张需求契约**（JSON/YAML）。契约填满 = 拿到完整需求，此后自主阶段直接读它跑，**中途不回头问用户**。三段式：

```
前置对话（−1）→ 需求契约拍板（0） → 后台自主执行到完成
```

这与项目「4 步 5 拍板点」框架兼容：前置对话是把原本被默认跳过的「物料在哪/给了啥/做几条/什么约束」从隐式假设变成显式首格，**不是新增用户负担，而是把本来就要知道的东西结构化收集**。

### 对话四规则（模型无关 · Claude Code 用 AskUserQuestion · 其他模型映射各自选择 UI）

1. **先开放后收敛**：开场一句自由话让用户倾倒，不上来逐条盘问。
2. **只问缺格**：LLM 解析开场话，只对没填的格子发定向选择题。
3. **能默认就默认**：把推断的缺省值写进契约草稿摆给用户，用户改哪格点哪格，而不是从零回答。
4. **告知契约即触发**：一旦需求契约拍板，明确告知「后面 agent 自主跑，X 分钟后来取结果」。

### 拍板前的「两拍小样」套路（适用于有渲染产物的 skill）

快速渲染产物类 skill 在完整自主执行前，插入「两拍」让用户找感觉：
- **拍 a（静态）**：秒级出关键帧/截图拼图，验静态成立（色板、景别、布局）。
- **拍 b（动态草稿）**：拍 a 过后，用 draft 模式（降质、跳门）出前几秒/前几镜动态粗剪，让用户感受运动/节奏/气质。
- 用户说「进」→ 才起完整自主成片；说「退」→ 退回分镜修改，不浪费完整渲染资源。

**两拍的价值**：拍 a 捡静态病（色板漂移、景别崩、纸桌分不开）；拍 b 捡动态感觉（运镜太飘、卡点对不上、整体气质不对）。两类病各在一拍发现，比「全片渲完再发现」早几十分钟。

### 「多视频」的默认语义

「做几个」最常见是**同素材多风格 A/B**（同一套立绘+音频，逐个配不同 style_pack + 创意），不是多曲多角色各做一条。契约里 `multi_mode: "style_ab"` 为默认；多曲/多角色各一条时切到 `single`，阶段 0 先拆物料再各自跑流程。

### 「多角色立绘↔歌词段映射」是两个独立问题

- **歌词↔时间**：可从音频/LRC 全自动推，不用问用户。
- **立绘↔歌词段**：音频推不出来；单角色自动 `all`；多角色须从用户处得到「谁唱哪段/轮流/合体」的映射草稿再确认，缺了这个多角色分镜没法排镜。

**Why:** 2026-07-27 设计 paperdoll-mv-packaging 前置对话时提炼——原 §9 假定三输入已就位，没有「物料在哪/约束是什么」的收集环节。把隐式假设变成结构化契约、插入两拍小样、用户拍板后才起后台自主，是把「前置所有决策 → 后台无干预」套路制度化。

**How to apply:** 任何有「用户给物料 → agent 自主产出渲染/生成产物」场景的 skill，都可套此三段式：(1) 设计一张需求契约 JSON schema，(2) 按四对话规则填满，(3) 可渲产物时插入两拍小样，(4) 用户说「进」后起后台自主。参考完整实现：`.agents/skills/paperdoll-mv-packaging/SKILL.md §9.0.1 / §9.0.2`。关联 [[feedback_full-autonomy-no-confirm]] [[project_user-agent-4step-workflow]] [[feedback_skill-vs-template-distinction]]
