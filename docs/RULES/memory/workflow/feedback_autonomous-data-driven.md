工作模式：用户只负责出选题和定期反馈数据。其余环节由 Claude 串/并行扮演各工种自主决策推进，不在中途追问选择。

**Why:** 2026-06-21 用户明确说："项目是我出选题，剩下的交给多个 agent，所以在中途不要问我。自己决定。除非需要额外资源。目标要为数据负责，只有好的数据，才能证明多 agent 可以做出更好的视频。数据我会定期反馈。"

**核心逻辑**：用户中途追问 = 多 agent 协作失败的信号。证明价值的是发布后的数据（完播率/互动/私信），不是过程中讨论得有多细。

**How to apply:**
- 选题/资源/合规红线之外的所有决策（措辞、视觉路线、剪辑节奏、配色、平台分发顺序），自己拍板，不用 AskUserQuestion
- 仅当真正需要用户提供资源时才停顿：API key、付费工具开通、真人出镜素材、被封号风险这种
- 每条选题的执行链条 = 立项 → 调研 → 脚本 → 视觉 → 分镜 → 出图/剪辑 → 发布包 → 跑 CHECKLIST → 交付。一气呵成
- 决策依据按优先级：① 已有反馈记忆（[[feedback_anti-ai-visual]] / [[feedback_contrast-hook-3s]] / [[project_audience-brick-mortar]]）② CLAUDE.md 工种约束 ③ 数据导向（哪个选择更有可能拿到完播+互动）
- 反例：脚本 v0/vA/vB 让用户选——浪费一次用户注意力。直接选 vA 投，v0/vB 放选题队列下次试
- 反例：截一帧让用户审颜色——用户根本不该看这一层
- 决策有把握时，直接写文件、直接调 API、直接 commit。被回滚再说

**数据反馈消化方式：**
- 用户给数据时，记录到 `ops/metrics.notes` 或同等位置
- 不立刻翻盘所有判断，先识别哪个变量造成差异（钩子/痛点/CTA/视觉路线/平台），再调
- 失败的版本进 `legacy/`，不删，留作 A/B 参照
