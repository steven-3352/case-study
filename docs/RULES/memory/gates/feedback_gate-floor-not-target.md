**门禁的语义永远是"地板"(最低及格线),不是"目标"。** 每到"我觉得这个能过门禁"的时刻,那个"能过"的感觉本身就是**该把标准往上抬的信号**,不是"可以交付"的信号。强制反问:**能不能把验收目标往上提 3 个档次?** 然后把抬高后的标准当成真正的验收目标去建,再验收。

**Why:** 用户 2026-07-21 在语音厅 MV 事故复盘后立的重要规范。此前反复踩同一坑:一有门禁(如"190px 位移底线")就建到刚过线就停,产物过了所有自建检查却依然难看/保守/单调(Goodhart:度量成了目标,只优化度量不优化度量背后真正想要的)。用户原话:"不要把底线当目标,所有认为可以通过的门禁,自己先问自己,能不能再往上提高3个档次的作为验收目标。"

**How to apply:**
- **触发时机 = 任何"它过了/能过/达标了"的判断点。** 内容 scorecard、gate_check_media、gate_check_palette、运镜/多样性 QA、脚本锦标赛、封面评审、pre_publish_forecast 评级——每一道打算因"过了"而放行的地方,先跑这个反问。
- **"3 个档次"= 刻意的实质性大跳,不是 +1 敷衍改良。** 逼自己从"最低可接受"心智切到"什么才算明显出色"心智。把抬高后的标准写成新的验收目标。
- **抬高的是"起手瞄准的目标",动手前设定。** 第一次就照抬高三档的标准去建、再验收;不是过后无限返工。
- **与闭环上限/D05 加速不冲突:** 那些管"失败后重做几轮(≤2)",本条管"第一次瞄多高"。先瞄高 + 返工有上限,两者相容。别把本条误读成"无限镀金"。
- **判据自查:** 若我放行的理由是"它过了 gate",停;问"过的是目标还是代理指标?这道地板是'好/出色'的代理,清了它等于什么都没说"。抬三档定义什么叫合格,再做。
