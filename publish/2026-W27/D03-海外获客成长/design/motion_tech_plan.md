## 适用性

逐镜说明 GSAP 数据动效相较"静态截图/纯字幕"为何更能服务明确的数据指标（含数据杠杆词）：

- **镜 1（曝光曲线上扬 + 焦点下移到空名单）：** 服务 **completion_3s（3s 停划）**。运动是最强前注意特征——曲线"正在动"+ 镜头下移到空名单的运动路径，比一张静态"曲线↑/名单空"截图更能在余光阶段抓住眼睛、压住信息流；数据杠杆=3s 停划。静态截图停划力弱、留不住第 1 秒。
- **镜 2（真界面四拍快切 + 上线戳记）：** 服务 **完播率 + 看懂**。GSAP 控制的提速快切（每拍≈2s、动作热点高亮逐拍切换）把"一天搭完全链路"做成有节奏的过程感，比四张静态截图并列更防中段拖沓、看懂更快；数据杠杆=completion_rate + 理解。
- **镜 3（Day 时间轴逐格点亮 + 邮件逐封飞出）：** 服务 **完播率 + 收藏**。这是全片最抓完播一段（对标 41.4% 标杆"系统自己跑"打法）。逐格点亮 + 逐封飞出让"系统 24/7 自己跑"肉眼可见、且时间轴是"被整理好的结构地图"（收藏钩）；静态截图无法呈现"一封封在发"的过程，看懂与收藏杠杆都掉。数据杠杆=completion_rate + 收藏。
- **镜 4（空栏→引流图运动路径交接 + 划走手势）：** 服务 **完播（回扣搭桥防流失）+ 评论**。GSAP 运动路径把视线从空栏带到引流图（反流失命门=每个交接都搭桥），划走手势制造"我也刷过这种图"共鸣；静态硬切会让眼睛重新找位置、产生流失点。数据杠杆=completion_rate + 评论。**背景层热点梗：** 翻车瞬间叠一个当下流行的"裂开/傻眼"反应贴纸 + 热点音效梗（守铁律①），作背景层情绪容器——压灰虚化退余光、音效走背景层音量，不抢"引流图被划走"单焦点、不盖 VO。
- **镜 5（左右分屏对比 + 右侧留资栏示意性轻入）：** 服务 **看懂 + 信任**。"差异本身当焦点"——左右并置让"机器味 vs 像人"一眼可辨，右侧留资栏示意性轻入呈现"开始有反应"（限示意、禁伪造改善证据，不出增幅/倍数）；fade 渐变或静态拼图看不到并置差异，对比力弱。数据杠杆=理解 + 信任（completion_rate）。
- **镜 6（自动跑全景 + 两段字幕逐句弹入）：** 服务 **评论 + 信任收束**。背景"邮件还在发"的轻动效坐实"它仍在替我跑"，两段（价值锚+CTA）逐句弹入按阅读顺序替观众翻页、CTA 问句末位收束（结论钩已前移 s3，末段两拍防末 5s 过载）。数据杠杆=评论。

> 总结：6 镜动效均能指名服务 completion_3s / completion_rate / 看懂 / 收藏 / 评论 中的具体一项，无"为动而动"。

## 可读性

9:16 小屏（1080×1920）文字 / 曲线 / 方向是否清楚、单焦点不被打散：

- **文字：** 大字钩子占屏宽 ≥80%、粗体高对比描边、≤1.5 行；正文/角标明度压低退背景层，与大字明度差分诊（主标题/副信息/装饰三层）。每镜出图后逐张目视检查叠层遮挡（留存铁律③）。
- **曲线/时间轴：** 曝光曲线只在镜 1 入场动一下即定、随后压灰，不在小屏持续干扰；Day 时间轴 6 格横排、当前格放大高亮、其余压灰，确保小屏一眼看清"亮的是哪一格"；点亮顺序=口播顺序，方向清楚。
- **邮件飞出：** 飞出方向统一从当前亮格发出、轨迹一致，避免满屏乱飞分散视线；同帧只允许一封在主运动。
- **分屏：** 左右各占半屏、明度交接（左暗右亮）锁视线到右侧；不做两屏同等亮度（否则乒乓）。
- **单焦点保证：** 每帧只一个运动赢家（见 storyboard 各镜 focus），其余元素压灰+虚化+不动退背景层（attention_guidance §3 分层/分时/梗当容器），已过「炫技毙否测试」——动效制造单焦点路径而非打散注意力。

## 资产

需要的真实素材 / 字体 / 数据结构 及能否落地：

- **真实落地页截图：** P001 海外获客项目真实落地页（hero 区）→ 本地 PNG，作镜 1 背景层与镜 2 拍 1。可落地（项目已有真实落地页）。
- **真实表单 / 邮件样式：** 收邮箱表单界面、欢迎信 + 养熟邮件真实样式 HTML/截图 → 镜 2 拍 2/3、镜 3 邮件飞出卡。仿真但结构可解释，**不冒充真实后台精确收件数**（守 fact_check）。
- **后台留资看板（GA4 风曝光曲线 + 留资名单列表）：** 仿真数据结构——曝光曲线数据点（仅示意上扬趋势，无精确数值上屏）；留资名单列表（呈现"空/个位数"空行，**不写具体数字、无金额/转化率**）。结构真实可解释问题，不 P 图假装真实后台；**仿真看板区常驻「示意数据」水印 + 与真落地页截图区视觉分界**（边框/标签），不混成一帧误读实时真后台。
- **Day 时间轴数据结构：** `[Day0, Day2, Day4, Day6, Day8, Day10]` 6 节点 + 每节点对应一封邮件类型（欢迎信/养熟），驱动逐格点亮与逐封飞出时间轴。可落地（GSAP timeline）。
- **改前改后出图素材：** 左=纯 AI 一键出图（机器味样例）、右=AI 只出背景+文字自排（像人样例）→ 真实出图素材本地 PNG。镜 5 分屏。
- **Pinterest 竖版引流图：** 镜 2 拍 4 + 镜 4 被划走的引流图 → 真实出图本地 PNG。
- **背景层热点梗素材（镜 4）：** 当下流行的"裂开/傻眼"反应贴纸（PNG/透明，背景层用）+ 对应热点音效梗（背景层音量）→ 取当期平台流行梗，作背景层情绪容器，压灰虚化退余光、音效不盖 VO；可落地（轻量素材，不抢主运动赢家）。
- **字体：** 项目统一中文黑体（大字钩子）+ 数据界面等宽/无衬线（看板/邮件），随项目字体栈，已就绪。
- **GSAP：** 项目已装 GSAP Skills（`.agents/skills/` 8 个），timeline/core 足以驱动逐格点亮、飞出、分屏、曲线，无需额外依赖。

## 导出

HTML+GSAP → 截帧/录屏 → 合成 mp4 的稳定路径：

- **路线 A（首选 · 截帧合成）：** HTML+GSAP 场景按帧驱动 → Playwright/Chrome 逐帧截 PNG（9:16 满铺 1080×1920，参考 `pipeline/gen_evidence.py` Chrome 渲 HTML 出满铺帧）→ ffmpeg 序列帧合成 mp4 → 叠 VO（Edge/MiniMax TTS，见 audio_plan）+ BGM + 字幕帧 overlay（HTML 帧 overlay，ffmpeg 无 libass）。参考 `pipeline/p004_video/build.py`（HTML+GSAP 渲染场景→PNG→mp4+VO+BGM+字幕）。
- **路线 B（备选 · 录屏）：** 复杂连续动效（邮件逐封飞出长段）可整段录屏再合成，降低逐帧对齐成本。
- **稳定性：** 每镜独立 HTML 场景独立渲染再拼接，单镜失败不影响全片；时间轴/飞出用 GSAP timeline 精确控制帧时长，便于与 VO 重音词对齐（切换压在重音上）。
- **字幕：** 走 HTML 帧 overlay（项目既定方案，ffmpeg 无 libass），CTA 口播完整进片（VO≤45s，校验 VO 时长≤片长，守 §13.2 CTA 完整进片硬门）。

## 风险

逐项风险与控制（复杂度不拖节奏 / 不抢主信息 / 移动端观感 / 真实性）：

- **复杂度拖节奏：** 镜 3 时间轴 + 逐封飞出元素多，控制=每帧只一封主运动 + 当前格亮其余压灰，分时呈现不堆叠；单镜动效服从节拍表时长（镜 3 最长 9s、其余 2–8s），不为动效超时。
- **抢主信息：** 曝光曲线/成本角标/全景背景均压灰虚化退背景层（加料不加赢家），不做第二赢家；已逐镜过「炫技毙否测试」——制造单焦点路径，未打散注意力。
- **移动端小屏观感：** 大字 ≥80% 屏宽、时间轴 6 格横排放大当前格、分屏左暗右亮明度交接，确保小屏方向/文字/差异清楚；出图后逐张目视检查叠层遮挡。
- **真实性（不冒充真实后台）：** 看板/邮件/留资名单为**仿真但结构可解释**，留资仅呈现"空/个位数"、**不写具体数字、无金额/转化率/留资率**；曝光曲线仅示意趋势不出精确数值；改前改后用真实出图素材。守 fact_check 与留存铁律②（真实界面、禁抽象圆点/图标墙）。未使用 Three/Web3D（3D 粒子候选已在形式策略"炫技毙否测试"否决，因打散"6 封定时邮件"清晰结构）。
- **真假素材分界 + 示意水印（导出前硬检查项）：** 含仿真数据看板/留资曲线/留资名单的镜（1/3/4/5）导出前**逐镜硬检查**：①仿真区屏上**常驻「示意数据」水印/角标**，任一帧可读；②真实素材区（真落地页/真实出图）与仿真区（数据动效/看板）有**明确视觉分界**（分屏/标签/边框/底色），不混成一帧误读"实时真后台"；③镜 5 右侧留资为**示意性轻入 + 「示意」标注**，不出具体增幅/倍数/精确改善量（**禁伪造改善证据**）。任一项不过 → 不得 render 进成片。
- **导出对齐风险：** 逐帧截帧与 VO 对齐需精确——控制=GSAP timeline 标注每镜关键帧时间码，渲染前先对齐 audio_plan 的 VO 分段时长，再批量截帧，避免动效与口播错位。
