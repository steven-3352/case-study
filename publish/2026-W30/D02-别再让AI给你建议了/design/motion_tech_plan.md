## 1. 本条实际动效清单(逐条可行性审查)

### 动效1：④指令卡①"别夸我" + 指令卡②"编个陌生人"逐行显现 + 人称替换图示(0:14-0:20，6s)

- **实现路线：** 复用 T040④已验证的 HTML+GSAP TextPlugin 机制(逐字/逐行显现，精确控制缓动曲线和时间轴，与VO节奏对齐)，**不重新发明**。差异点：
  1. 卡片①"别夸我"只有4字，显现节奏改为"整体落定"感(短暂 `scale(0.9→1)+opacity(0→1)` 的"盖章确认"效果)而非逐字打字机——4字逐字反而显得拖沓，与T040④4行长指令的逐行打字机节奏不同，需单独设计缓动曲线
  2. 卡片②"编个陌生人，让AI评价ta"沿用逐行打字机(与T040④相同技法，文字量级相近)
  3. **新增元素(T040④没有)：** 人称替换小图示——两枚自绘简笔头像("我"/"陌生人TA")，GSAP timeline 驱动"我"头像先出现，随后横向滑出画面同时"陌生人TA"头像横向滑入(交叉位移，非fade叠化，确保观众能看清"替换"这个动作本身)
- **资产需求：** 无外部生成资产，纯文本内容(两条指令，来自 `script/T041_录音提词稿.md` ④段，已定稿不需再生成)+ 2枚自绘线性头像图标(简笔线条，非拟人卡通，符合 design_language §3"图标"组件规则)+ 项目已有的 GSAP timeline 能力
- **性能评估：** 单卡片文字timeline + 2枚图标位移，渲染负担低，与T040④同量级，P004管线已验证过类似任务，无性能风险
- **导出风险：** HTML→PNG序列→ffmpeg合成mp4，是P004已验证的标准链路，导出风险低
- **可行性结论：** ✅ 可行，复用项目已有 GSAP skills，不需要新安装依赖
- **任务清单：**
  1. 写两个独立 HTML 场景(暖白`#faf9f6`底，mono字体)：卡片①短句落定效果；卡片②逐行显现+头像替换
  2. 卡片①：GSAP `fromTo(scale:0.9→1, opacity:0→1)`，约0.4s完成，停留至0:17.5
  3. 卡片②：GSAP timeline 逐行 `fromTo(opacity:0→1, x:偏移→0)`，每行间隔约0.6s；并行 timeline 驱动头像替换(0:18.0起横向滑出/滑入，约0.6s完成)
  4. 截帧(`capture_frames.py`) → PNG序列 → ffmpeg 合成进④片段
  5. 末尾caption"↓可截图拿走"停留至0:20，给观众截图时间

### 动效2：⑤双源漏斗收拢(0:20-0:23，3s，全片完播顶点前置动效)

- **实现路线：** 新建 HTML 场景，左右两栏分别渲染 claude-opus-4-8 / gpt-5.5 的真实文本片段(来源：`publish/2026-W30/D01-让AI说真话致命漏洞/design/实测_致命漏洞法.md` 两模型各自"B·实验组"段落)。GSAP timeline 驱动：
  1. 0:20-0:21.5：左右徽标+真实文字片段依次浮现(`stagger`)，让观众先看清"这是两个真测的模型"
  2. 0:21.5-0:23：左右两个文本容器同步 `scale(1→0.15)` + `x/y` 向画面中心 `translate` 收拢(向心运动)，配合 `opacity` 在收拢后段快速降低(避免收拢到中心时文字重叠糊成一团、显得潦草)
  3. 收拢完成的瞬间(0:23.0)与后续⑤c金句放大场景做**帧锁交接**(收拢终帧的中心点=金句场景的展开起点，视觉连贯)
- **资产需求：** 真实两模型输出文本(已有，`实测_致命漏洞法.md`) + 2枚模型徽标(自绘文字标签，非官方logo——避免品牌商标风险，与T040④"不带出品牌UI"的合规口径一致)
- **性能评估：** 双元素同步 tween，无3D/复杂计算，与④同量级，无性能风险
- **导出风险：** 低——沿用已验证的HTML→PNG序列→ffmpeg合成链路；**唯一风险点：收拢动画的精确时长(1.5s)必须严格对齐VO"分析秒收成一句"的实际语速**，VO录制后若实际语速与预估(6字/s)有出入，需回填调整 timeline 总时长参数重新截帧(成本低，改配置而非重录，同T040②③的经验)
- **可行性结论：** ✅ 可行，但**是本条技术风险最高、时间精度要求最高的一镜**——因为这是"全片最重一锤"，落点偏移会直接稀释completion_rate杠杆，建议 production 阶段优先调校此镜
- **任务清单：**
  1. 建双栏证据卡HTML模板(surface底`#eeece5`分隔线，body字级真实文本，2枚自绘徽标)
  2. 先出VO音频(见 `audio_plan.yaml`)，拿到⑤段精确时长
  3. 按精确时长设置 timeline 收拢速度+落点时间参数
  4. `capture_frames.py` 截帧 → PNG序列 → 按 build.py 标准链路合成
  5. 与⑤c金句放大场景做帧锁交接(收拢终帧=金句展开起点，参考T040②③帧锁经验但非同一素材复用，是独立的两个场景做交接对齐)

### 动效3：②zoom-out揭示真实长文(0:04-0:08，4s)

- **实现路线：** 新建 HTML 场景，真实长文(gpt-5.5"对照组"长回复，来源同⑤模型文本文件)渲染进自绘长文卡片。GSAP timeline 驱动容器 `scale`：起幅 `scale(4.0)` (只见几个字的极近特写) → 4s内连续 `scale` 递减至 `scale(1.0)` (全貌落幅，露出该句只是长文中一小行)。**与T040②的滚动(`scrollTop`纵向平移)是完全不同的动效语言**——本条是景别变化(镜头拉远)，不涉及内容滚动。
- **资产需求：** 真实 gpt-5.5"对照组"长回复文本(已有，`实测_致命漏洞法.md`)渲染进自绘长文卡片HTML模板(需新建，非复用T040任何模板)
- **性能评估：** 纯文字+CSS `transform: scale()`，无3D/复杂计算，性能负担低于T040②的`scrollTop`+`filter:blur()`组合，无性能风险
- **导出风险：** 低——沿用已验证的HTML→PNG序列→ffmpeg合成链路；**风险点：极近特写(scale 4.0)时文字渲染清晰度需在1080宽画布下实测校验，避免特写阶段文字模糊/锯齿**
- **可行性结论：** ✅ 可行
- **任务清单：**
  1. 建自绘长文卡片HTML模板(canvas暖白底，body字级，真实文本填入)
  2. 定位需要"被埋没"的那句真实批评性原句在长文中的具体位置，作为 scale 动画的锚点(`transform-origin`)
  3. GSAP timeline：0:04-0:06 保持极近特写(scale 4.0，微小呼吸感)；0:06-0:08 `scale` 连续递减至 1.0
  4. `capture_frames.py` 截帧 → PNG序列 → 标准链路合成

### 动效4：③确信勾号+赌注条 stagger 编排(0:08-0:14，6s)

- **实现路线：** 新建 HTML 场景，计划卡("举个例子·辞职做AI代运营"，复用⑤/②同一份底层真实测试案例的计划描述文本)+ SVG 勾号图标 + 进度条(bar)组件。GSAP timeline：
  1. 0:08-0:10：勾号 `stagger` 连续 pop-in(约每0.5s一个，`scale(0→1)+opacity`)
  2. 0:10-0:12.5：进度条(bar) `width` 匀速增长 + 勾号继续增加(与③b动作并行的同一条timeline)
  3. 0:12.5-0:14：所有元素定格，**timeline 到此不再新增任何元素**(警示图标位置刻意留空，这是"无动作"的设计决策，不是遗漏)
- **资产需求：** 计划卡文本(复用同一份"辞职做AI代运营"案例) + SVG勾号图标(简笔线性，非emoji) + 进度条组件(纯几何形状，无数字标签避免误导为真实数据)
- **性能评估：** 多元素stagger编排，量级与T040④指令卡逐行打字机相近，无性能风险
- **导出风险：** 低——标准HTML→PNG→ffmpeg链路
- **可行性结论：** ✅ 可行
- **任务清单：**
  1. 建计划卡+勾号+进度条HTML模板(canvas暖白底)
  2. GSAP timeline：勾号stagger pop-in + bar width tween，两者共享同一条 timeline 保证节奏统一
  3. 0:12.5起 timeline 无新增关键帧，保持静止到0:14(留白设计)
  4. `capture_frames.py` 截帧 → PNG序列 → 标准链路合成

## 2. 排除的动效方案(曾考虑但主动排除)

| 曾考虑 | 排除理由 |
|---|---|
| ④复刻T040"真实打字闪回"(真人录屏敲入指令) | T041脚本本身无"后来我多打一句"这类"真实操作"叙事支点(T040④有明确的"真操作过"证明需求，T041④是"给你两个笨办法"的建议式表达，不需要用真实录屏证明"我做过")，强行加入会显得为了凑素材而凑，非内容驱动，排除 |
| ⑤沿用T040"静态左右分屏"呈现双模型结果 | 直接复制T040⑤镜头机制，违反`no_clone_previous_topic`硬规；且本条"两个模型独立印证"的核心信任逻辑用"收拢汇聚"比"静态并列"更能传达"殊途同归"的说服力，改用双源漏斗收拢 |
| ③用真实百分比数字仪表(如"确信度87%")包装赌注/确信隐喻 | 这类具体数字并非任何真实测量结果，若渲染成"87%"这类精确数字会被观众误认为真实统计数据，违反 fact_check 红线；改用无数字标签的纯视觉隐喻(勾号数量+进度条长度)，保留直觉传达但不编造具体数值 |
| ②用GSAP `scrollTop`滚动(套用T040②机制) | 直接复制T040②镜头机制，违反`no_clone_previous_topic`硬规；且本条揭矛盾段的叙事重点是"原来一直都在，只是没注意到"(顿悟感)，zoom-out镜头运动比滚动更贴合"突然看清全貌"这个心理过程 |
| ⑥用GSAP 3D翻转展示"阶段轴" | catalog engine_3d family tech_risk=高且需声明数据杠杆，本条阶段轴的数据杠杆是"理解·信任"(直觉判断为主)，3D炫技不服务这个杠杆，且与本条"克制"视觉气质相反，排除 |
