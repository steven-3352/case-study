## 1. 本条实际动效清单(逐条可行性审查)

### 动效1:①钩子删除线(0:02-0:03.5,1.5s)

- **实现路线:** HTML+GSAP DrawSVGPlugin——在"我该怎么办"四字下方预置一条 SVG path(水平直线,accent色`#c0392b`,2-3px粗),初始 `drawSVG:"0%"`,GSAP tween 到 `drawSVG:"0% 100%"`,0.4s 内扫过完成,略带手绘感的 `ease: power2.out`(避免机械匀速显得像UI进度条)
- **资产需求:** 一条SVG path(可代码内联生成,不需外部素材文件)
- **性能评估:** 单条path描边动画,渲染负担极低,与项目已验证的HTML截帧任务同量级
- **导出风险:** 低——HTML→PNG序列→ffmpeg合成mp4,标准链路
- **可行性结论:** ✅ 可行,复用项目已有 GSAP skills(DrawSVGPlugin属付费GSAP插件,需确认项目GSAP授权是否含Club GreenSock插件;若未授权,备选方案为纯CSS `stroke-dasharray`+`stroke-dashoffset`动画,视觉效果等价,零额外依赖——**建议直接用CSS方案,避免插件授权不确定性拖慢排期**)

### 动效2:②反转箭头图标(0:07-0:08.5,1.5s)

- **实现路线:** 单个线性SVG箭头图标(180度U形转向箭头),GSAP `rotation:0→180` + 定格,配合"反过来"文字GSAP `scale:0.9→1.05→1` 轻微弹入(不做玩具化夸张弹跳,幅度控制在5%以内)
- **资产需求:** 1个线性图标——建议从 MIT/CC0 授权图标库(如 Lucide/Feather)取"corner-up-left"或"rotate-ccw"类图标线稿,自行按 ink/accent 色重绘描边,非直接引用带品牌标识的图标包;若自绘更省事(单条SVG path),直接手写亦可,成本相当
- **性能评估:** 极低,单图标单tween
- **导出风险:** 低,标准链路
- **可行性结论:** ✅ 可行,资产成本低,无授权风险(自绘或MIT/CC0图标线稿去标识化)

### 动效3:③④⑤清单卡逐行显现(0:10-0:25,15s,三档差异化参数)

- **实现路线:** 沿用 T040 motion_tech_plan 已验证的**同一套机制**——新建3个独立HTML场景(t042_03/04/05),每个场景内是一张 memo 卡片(surface浅暖灰底`#eeece5`,mono/data字级问题文本),GSAP timeline 驱动每行文字 `fromTo(opacity:0→1, y:12px→0)`,`registerTimeline(tl)` 交给 `capture_frames.py` 做确定性逐帧渲染。**三档参数差异(核心设计点,非技术难点,是节拍要求):**
  - ③(0:10-0:15,5s):4行显现,行间隔 0.7s,常速
  - ④(0:15-0:19.5,4.5s):2行显现,首行更大字号(display级)+ 显现速度放慢至0.8s + 显现后额外0.4s定格(呼应VO情绪停顿),**此场景的timeline总时长对VO精确停顿位置最敏感,需VO定稿后精调**
  - ⑤(0:19.5-0:25,5.5s):3行显现,行间隔压缩至0.4s,加速感
- **资产需求:** 真实文本内容(9问,来自 `raw-export/raw/2026-07-15-bot.md` L36-53 参谋 system prompt 原文,已定稿不需再生成)+ 项目已有GSAP timeline能力
- **性能评估:** 与T040④同量级(单卡片多行文字timeline动画),渲染负担低,P004管线已多次验证,无性能风险
- **导出风险:** 低——HTML→PNG序列→ffmpeg合成mp4,标准链路;**唯一风险点**:④场景的0.4s定格时长若VO实际停顿与预设(0.3-0.5s区间)有出入,需要改一行duration参数重新截帧(成本低,非重录,因为本条无真实录制环节)
- **可行性结论:** ✅ 可行,技术上是T040④的直接复用(参数化为3份),无新技术风险;**唯一执行顺序约束**:④场景的精确定格时长需VO精确时长回填,其余场景不受此约束

### 动效4:⑥卡片收拢+空checkbox(0:25-0:26.5,1.5s)

- **实现路线:** ③④⑤三个场景各自已渲染出"卡片完整态"的一帧,本场景将其缩放(`scale:1→0.35`左右)+ 位移(移动到画面上方排成一排)+ 每题旁追加一个空心方框SVG icon(`stroke`描边,无填充,**不触发任何勾选/填色动画**——这是红线约束,不是留白疏忽,需在渲染验收时人工确认无胜利感元素)
- **资产需求:** 复用③④⑤渲染产出的卡片截图/DOM状态(非重新设计新素材)+ 简单空心方框SVG(自绘,4条边path)
- **性能评估:** 低,标准缩放位移tween
- **导出风险:** 低;**有渲染顺序依赖**——③④⑤先出片,⑥的卡片缩略才能引用其视觉产出,顺序:03→04→05→06
- **可行性结论:** ✅ 可行,但需按顺序渲染,已记入下方任务清单顺序

### 动效5:⑦CTA卡片拼合(0:30-0:32,2s)

- **实现路线:** 非简单缩放堆叠,是**重新排版**——将③④⑤的9问文本以compact布局(3小节标题+问题列表,行距/字号缩小)一次性组装进单张完整清单卡,GSAP做卡片"拼合"位移动画(3个来源缩略图同时向中心汇聚,硬切定格,非fade),完成后即为收藏物最终形态
- **资产需求:** 9问文本(复用③④⑤同一份数据源)+ 新的compact排版HTML模板(需新建,非简单复用③④⑤的模板参数)
- **性能评估:** 低,纯DOM排版+位移动画
- **导出风险:** 低;**同样有渲染顺序依赖**(需③④⑤内容先定稿,虽不需要③④⑤的渲染产出,但需要同一份文本数据源保持一致)
- **可行性结论:** ✅ 可行

## 2. 排除的动效方案(曾考虑但主动排除)

| 曾考虑 | 排除理由 |
|---|---|
| ③④⑤用同一个HTML模板只改文本(不做三档参数差异化) | 会导致"清单卡片连续播15s观感雷同",违反反同质硬规每2-4s变化的要求;已按 retention_beat_sheet/motion_storyboard 的三档节奏设计(常速→放慢→加速)拆成3个独立模板 |
| ⑥用"打勾动画"或"金色高亮"庆祝式呈现收尾 | 直接违反本条核心红线——不能把"没拿到答案"处理成"AI给出完美方案"的爽感,空checkbox+平静字色是硬约束 |
| ①删除线用Lottie动画库 | 引入新依赖(Lottie运行时+设计工具链)服务一个1.5s的简单描边动画,成本收益不对等;CSS `stroke-dashoffset` 或 GSAP tween 已足够,排除 |
| ③④⑤为增强"证据感"强行加一段模拟"AI打字生成"的UI窗口壳(如T040④的思路) | 本条无真实操作可佐证,伪装"AI正在生成"这个UI窗口感反而是在编造证据——本条的真实性锚点是"文本内容本身来自真实原矿",不需要靠UI壳装饰;已在 motion_storyboard §2.2 改良说明中排除 |
