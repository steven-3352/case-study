## 1. 本条与 T040 的关键差异(先说明,避免技术方案照搬内容)

- **无真实素材/无长文档证据/无真人录制**:T040 有真实 gpt-5.5 长文输出 + 真实打字闪回录制(raw);T043 全部内容是**自绘UI + 自绘图标 + 典型化改写文案**,不涉及任何真实产品截图或真实屏幕录制——因为 (1) 核心"证据"是一个机制模式而非某次具体真实输出,展示逐字真实文本反而有隐私/合规风险(素材来自 Hermes 原矿 reddit 方向真实事件,画面侧禁止出现具体项目/平台细节);(2) 工作向框定要求容器统一自绘工作卡片,真实产品UI截图无法保证不带出品牌/社交语汇。**结论:本条无 `type: broll` 场景,全部为 `type: html`**,比 T040 少一个真实录制合规审核环节

## 2. 本条实际动效清单(逐条可行性审查)

### 动效1:①设备切换 + AI回复大字砸入(0:03.0-6.5,3.5s)

- **实现路线:** CSS transform 图标滑出滑入(设备切换)+ HTML drawtext 大字直砸(无GSAP,复用P001静态合成能力即可,成本最低)
- **资产需求:** 自绘线性图标(手机/电脑轮廓,非品牌logo),自绘工作向系统消息卡模板
- **性能/导出风险:** 低,标准HTML→PNG序列→ffmpeg合成
- **可行性结论:** ✅ 可行,无需GSAP,P001路径即可完成

### 动效2:②双设备记忆孤岛信号动画(0:06.5-12.3,5.8s)★本条核心新动效

- **实现路线:** 新建HTML场景,双面板(手机/电脑各占约45%宽度,中间留虚线通道),GSAP timeline 驱动一个圆点沿SVG path从左面板移动到通道中点,`onComplete`触发"⊘"断连符号淡入+圆点缩放消散(粒子效果用简单CSS scale+opacity,不做复杂粒子系统,避免过度炫技),`registerTimeline(tl)` 交给 `capture_frames.py` 截帧——与④清单卡走**同一套确定性截帧机制**,非独立新基建
- **资产需求:** 自绘双面板HTML模板(surface浅灰底,ink深字标签)+ 自绘SVG图标(文件夹/⊘断连符)
- **性能评估:** 单一路径动画+简单缩放消散,渲染负担低,与T040④同量级,P004管线已验证过
- **导出风险:** 低,唯一需要精确调校的是"信号撞墙"时间点必须与VO"互相看不见"的落字时间对齐(10.8s处),这是时间轴精度问题非技术可行性问题
- **可行性结论:** ✅ 可行(五维打分已在 `form_strategy.md` §2 独立完成,方案B总分27显著优于静态方案)
- **任务清单:**
  1. 建双面板HTML模板(canvas暖白底,surface浅灰面板,accent色⊘断连符)
  2. GSAP timeline:0-2.0s面板滑入,2.0-4.0s信号点沿path移动(offsetPath或手动插值x/y),4.0s触发断连符号+消散
  3. `capture_frames.py` 截帧 → PNG序列 → ffmpeg合成进②片段
  4. 与sfx对齐:信号撞墙瞬间(全片绝对时间10.8s)需精确对应 `audio_plan.yaml` 的hit事件

### 动效3:③聚焦孤立对话 + 未达成态图标(0:12.3-17.3,5.0s)

- **实现路线:** CSS blur蒙版(局部虚化)+ GSAP局部放大(zoom至左面板内一条对话条),复用②双面板场景资产,非独立新场景
- **资产需求:** 复用②面板资产 + 新增"远处灰置共享位置图标"(云朵/文件柜SVG)+ 红色✕
- **性能/导出风险:** 低,与②同一套渲染管线延伸
- **可行性结论:** ✅ 可行,依赖②场景先完成基础资产(渲染顺序:②→③)

### 动效4:④⑤三步清单卡逐行GSAP(0:17.3-31.0,13.7s)

- **实现路线:** HTML+GSAP TextPlugin/fromTo(逐条卡片opacity:0→1 + y偏移),与T040④指令卡走**完全相同的机制**(catalog `kinetic_typography`),仅内容替换为3步记忆设置法,非"套模板"而是复用已验证有效的技术手段
- **资产需求:** 自绘清单卡模板(canvas暖白底,mono/data字体,文件夹/云朵/日历三个SVG图标),4条+汇总态共用一个模板不同data参数
- **性能评估:** 与T040④同量级,极低性能风险
- **导出风险:** 低,标准链路
- **可行性结论:** ✅ 可行
- **任务清单:**
  1. 写清单卡HTML场景(暖白底,mono字体,3个SVG图标位),GSAP timeline逐条显现,每条间隔按motion_storyboard §3各子段时长设置(①②③步分别约2.0/2.1/2.0s显现窗口)
  2. ②卡片显现后追加"重连动画"子timeline:复用②场景的双面板+连接线资产,虚线→实线过渡(约1.0-1.5s,置于22.8-24.9s窗口内)
  3. 汇总态(29.0-31.0s):三卡合并视图 + caption"↓可截图拿走"
  4. 截帧→合成,与④⑤共用一个渲染任务(同一模板不同data.stage参数,减少模板数量)

### 动效5:⑥风险条数据动画(0:31.0-35.3,4.3s)

- **实现路线:** GSAP width数值动画驱动一个横条从100%收缩到约15-20%(具体数值不代表真实统计,仅为"大幅降低但非0"的示意,需在文案/caption标注"示意非精确统计",避免被误认为真实数据造假),catalog `data_viz_motion` 标准用法
- **资产需求:** 简单CSS横条+GSAP,无外部数据源
- **性能/导出风险:** 低
- **可行性结论:** ✅ 可行,但需在渲染任务清单里显式加一条"条形收缩比例仅为示意,非真实统计数字"的免责标注,避免过审时被事实核查误判为编造数据

### 动效6:⑦评论区mock + 问句大字(0:35.3-38.5,3.2s)

- **实现路线:** 自绘工作向评论区UI mock(方框输入框+文字,非社交软件圆形头像楼层)+ `punch_black`式大字浮现,无GSAP必要,P001静态合成即可
- **资产需求:** 自绘评论区UI模板
- **性能/导出风险:** 低
- **可行性结论:** ✅ 可行

## 3. 排除的动效方案(曾考虑但主动排除)

| 曾考虑 | 排除理由 |
|---|---|
| ②双设备孤岛直接复用T040⑤`before_after`左右分屏的静态对切手法 | 已在`form_strategy.md`§2五维打分证明:静态对切(方案C,总分19)理解成本高于信号动画(方案B,总分27)——对比手法适合"揭晓反转",不适合"演示因果",本条数据杠杆是"理解因果"而非"对比揭晓" |
| ①②③容器沿用T040①"自绘对话气泡"圆角气泡样式 | 圆角气泡+尾巴的容器语汇是本条最大误读风险源(小红书"AI失忆"话题顶流是情感陪伴人群,气泡语汇天然引导向"聊天/陪伴"联想),即使内容文本是工作向措辞,容器形状本身也会传递错误信号,故全部改为矩形工作卡片/系统消息条容器 |
| ②用真实产品截图录制"双设备切换"过程(而非自绘动画) | (1)隐私风险:真实操作可能带出侧边栏历史会话;(2)合规风险:素材背景来自Hermes原矿reddit方向真实事件,画面不得出现具体项目/平台细节;(3)自绘信号动画能更精确演示"互相看不见"这一抽象因果关系,真实录屏反而做不到这种解释力 | 
| ⑥用真实用户反馈数据做风险条(如"据统计丢失率降低XX%") | 无真实统计数据来源,编造具体数字违反fact_check红线;改用"示意非精确统计"的抽象条形动画,只传达"大幅降低但非0"这一定性结论,与口播"没人敢保证百分百不忘"的诚实红线一致 |
