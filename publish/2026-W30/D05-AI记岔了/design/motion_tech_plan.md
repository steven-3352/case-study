## 1. 本条与 T040/T043 的关键差异(先说明,避免技术方案照搬内容)

- **不出镜承载③情绪**:T044 情绪弧线比 T040(纯证据流,无情绪叙事)更明显,但本条**未激活出镜扩展工种**(演示型默认不出镜),③"崩溃点题"的情绪完全靠 UI 帧锁定格+局部虚化+大字punch 承载,不新增任何真人素材需求——这是本条相对 T040/T043 都没有出现过的技术选择(T040/T043 均无出镜环节,本条同样延续"不出镜",但因情绪密度更高,需要更精细的定格+虚化时机把控,单独说明)
- **⑥双通道验证法为轻量图标级设计**:已在 `form_strategy.md` §2 完成独立五维打分,明确排除"仿T043②完整双设备面板"方案,技术方案相应更轻(无需搭建两个完整UI面板容器,只需图标+文字条+同步标记)

## 2. 本条实际动效清单(逐条可行性审查)

### 动效1:②搜索列表扫描高亮(0:04.8-0:12.3,共7.5s,含打字+两段扫描+反转)

- **实现路线:** 新建HTML场景,矩形手机工作卡片模板;打字段(4.8-6.8s)用CSS `steps()`打字机效果模拟逐字符浮现,无需GSAP;两段列表扫描(6.8-9.0s聊天记录、9.0-10.6s笔记)各自是一个独立列表组件,GSAP `stagger`依次高亮列表条目背景色(短暂accent浅色闪过再复位),制造"AI在逐条比对"的视觉;反转揭晓(10.6-12.3s)是系统消息卡文字落定,复用P001 drawtext即可,不需要GSAP
- **资产需求:** 自绘手机工作卡片模板(暖白底)+ 两套列表组件(聊天记录列表标签、笔记列表标签,图标明显区分,避免观众误认为同一个列表播了两遍)
- **性能评估:** 纯CSS打字+GSAP stagger(条目数量约4-6条),渲染负担低,P004管线已多次验证过类似量级任务
- **导出风险:** 低——沿用HTML→PNG序列→ffmpeg合成标准链路;唯一需要精确调校的是两段扫描节奏需与SFX tick对齐,不对齐会显得"扫描"和"声音"脱节
- **可行性结论:** ✅ 可行,复用项目已有GSAP skills(stagger技法)
- **任务清单:**
  1. 建手机工作卡片HTML模板(暖白底,矩形容器,打字机CSS动效)
  2. 建两套列表组件(不同图标/标签,GSAP stagger高亮扫描,每条约0.3s)
  3. 建系统消息卡子模板(反转揭晓态,drawtext即可)
  4. `capture_frames.py` 截帧 → PNG序列 → ffmpeg合成进②片段

### 动效2:③帧锁定格+局部虚化(0:12.3-0:16.5,4.2s)

- **实现路线:** ②场景的最终渲染帧(系统消息卡"没有这条线"落定态)作为③的起始帧,**像素级复用**(非重新渲染一份相似画面),CSS `filter:blur()` 对周围区域做局部虚化(不透明度降至35%,非变暗)+ GSAP 对消息卡本体做轻微放大(zoom to ~115%),14.3s后叠加大字punch(P001 drawtext,无GSAP)
- **资产需求:** 复用②-3反转揭晓的渲染产出(非新素材)
- **性能/导出风险:** 低,CSS blur蒙版+GSAP局部放大是P004管线已验证过的手法(同T040③红框定位镜同量级)
- **可行性结论:** ✅ 可行,**有渲染顺序依赖**(②先完成渲染,③才能引用其最终帧做帧锁),`[[feedback_frame-locked-seam]]`已在本文件+form_strategy.md两处标注
- **任务清单:**
  1. ②场景渲染完成后,截取其最终帧作为③起始素材
  2. GSAP局部放大+CSS blur蒙版,时长2.0s(12.3-14.3s)
  3. 14.3s后接大字punch两句(P001 drawtext,静态合成)

### 动效3:④AI补充消息逐行显现 + 三节点流程图(0:16.5-0:22.8,6.3s)

- **实现路线:** 与T040④指令卡走**相同机制**(catalog `kinetic_typography`):HTML+GSAP TextPlugin/fromTo逐行opacity:0→1;紧接着(18.5-20.7s)三节点流程图用GSAP timeline逐点触发opacity+scale进场,节点间连接线用简单的`stroke-dashoffset`动画模拟"draw-on"效果(非引入DrawSVG插件,项目已有GSAP核心能力即可实现,降低依赖);20.7-22.8s文字结论落定+流程图整体定格,复用同一模板不同`data.stage`参数
- **资产需求:** 自绘AI消息卡模板(暖白底,ink深字)+ 自绘三节点SVG(简单圆点+连接线,非复杂图标)
- **性能评估:** 单卡片文字timeline+3节点SVG动画,渲染负担低,与T040④同量级,无性能风险
- **导出风险:** 低——沿用标准HTML→PNG序列→ffmpeg合成链路;**本条使用GSAP,已触发门禁,本文件即完成该门禁要求的可行性审查**
- **可行性结论:** ✅ 可行,复用T040④已验证的GSAP逐行技法,流程图连接线用项目已有能力(stroke-dashoffset)实现,不新增插件依赖

| ④三节点流程图用真实录制素材(如真实录一遍"没走收尾"的操作过程) | (1)本条核心事件是"举例概括"处理(script红线自查已明确不带具体真实项目名),若配真实录制素材反而会暴露具体操作细节,与"某个方向"的概括处理矛盾;(2)自绘流程节点图能更精确地把"聊完→没走收尾→没记进本子"这个抽象因果链可视化,真实录屏做不到这种结构化解释力 |
| ⑥双通道用真实两台设备实拍对比 | (1)隐私/合规风险:真实操作可能带出侧边栏历史会话或账号信息;(2)"抓包验证法"是一个方法论动作而非某次具体真实测试,自绘图标+文字条演示比实拍更适合传达"这是个通用可执行技巧"而非"这是我这一次的真实操作记录" |
| ②搜索动效用真实App录屏(真实打开某AI应用做搜索操作) | 与T043相同理由:隐私(可能带出侧边栏/历史会话)+合规(避免暴露具体产品UI/logo)双重风险,自绘列表扫描高亮已能清晰传达"AI在认真找"这个意图,且两个列表(聊天记录/笔记)的视觉区分可以自由设计,不受真实App界面限制 |
