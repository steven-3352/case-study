# 立绘卡点 MV 通用制作 Playbook

> **定位**：客户借用本引擎能力的独立方向（角色立绘 + 歌曲卡点），与项目主旨（AI 内容自动化生产、观众-first 洞察→分镜→出片）**分线管理**。本文只回答"这类客户活儿怎么做才对"，不进 `templates/`，不进 `pipeline/` 一级目录，不改 SYSTEM.md。

---

## 1. 参照视频拆解（流云·极梦《最浪漫的话："我愿意"》）

### 1.1 硬指标

| 项 | 值 |
|---|---|
| 分辨率 | 1024×576（**16:9 横版**，非 9:16） |
| 时长 | 52.4s |
| 帧率 | 30fps CFR |
| 码率 | ~1.24 Mbps H.264 High@L3.1 |
| 音频 | AAC HE-AACv2 44.1k 62kbps 立体声 |
| 实际硬切数 | **3 次**（10.3s / 30.2s / 38.0s，scene threshold 0.3） |

**结论**：不是快切 MV，是**慢镜叙事 + 内镜运动**。每段场景长 8–20s，情绪靠层内动效撑，不靠剪辑节奏撑。

### 1.2 表现形式 · 3 个可辨识信号

**A. 立绘 + 视差动态化（不是 Live2D 骨骼）**
参照片主视觉是**静态动漫立绘**（男主：银发+黑色龙纹长袍；女主：白发蒙眼纱+捧花婚纱），在此之上叠加：
- 前景/背景分层的**慢缓视差 pan**（1–2% 幅度，模拟"镜头轻推 / 呼吸"）
- 头发/裙摆的**局部循环飘动**（PNG 分层 + Warp 或 AI 图生动画短循环）
- **不是 Live2D 骨骼绑定**——若是 Live2D 会有嘴部/眼球连续同步、面部 kf；参照片全程角色**不说话不眨眼**，纯"活起来的画"

**B. 大字歌词卡点（Kinetic Typography, 竖排 + 副 tag）**
每次歌词击点（重音 / 尾音收 / 副歌进入），一个**大字**从画面左侧或中央撞入：
- 主字（60–120pt 明朝/宋体）+ **括号副 tag** `[想见你]` / `[我愿意]` 装饰
- 出现方式：淡入 + 微向下移动 + 3–5 帧后加轻微 blur/glow 稳定
- 位置：左下 1/3 或画面中央，避让人物脸部
- 与人物图层用**发光边 / 混合模式 screen** 叠加而不是纯 alpha

**C. DV 摄录机 UI 边框（情感锚）**
从 ~24s 起（进入副歌/情感段）叠加**假 REC 取景框**：
- 左上 `RECORDING`、左下 `● REC 1920×1080 · MNL/OPEN/1/125/3dB`
- 右下电池图标 + `1h 13m` 假时长
- 底部**假时间码 `00:00:11 → 00:00:25`** 递增（伪装成"回放的珍贵录像"）
- 作用：把观众放到"我在偷看这段珍贵录像"的位置，情绪 +1 档

### 1.3 层次结构（合成栈自下而上）

```
[8] 品牌水印 "Ly.<角色名>"（每段跟着此段主角切换 tag）
[7] DV 边框 UI（副歌段激活）
[6] 大字歌词层（击点触发）
[5] 前景飘物：碎屑 / 光斑 / 雪 / 星（粒子）
[4] 光效层：光束、镜头眩光、色差 chromatic-aberration
[3] 人物立绘（分层：头发 / 身体 / 服装边缘各自轻扰动）
[2] 环境素材（钟表、街灯、月亮、天空、几何粒子环）
[1] 底色（黑或深蓝渐变）
```

### 1.4 音画同步节律

| 时段 | 音频 RMS | 视觉状态 |
|---|---|---|
| 0–10s | 弱起 -13.5dB | 男主单角特写 + "失去" 大字 |
| 10–22s | 建构 -11dB | 男主+景切换 + 大字 3–4 击 |
| 22–30s | 抬升 -9dB | 双人对峙 + DV UI 上 |
| 30–38s | 副歌 -8.5dB | 手交握特写（情绪高点） + "会不会" |
| 38–52s | 尾段收 -8.8dB | 双人蓝天定格 + "在等待一句" + fade |
| 52s | -38dB | 收尾 |

**关键规律：硬切=段落分界，不是节拍分界。**节拍震动全部由**大字弹入 + 光效脉冲 + 立绘 3–5% zoom-in**在场景内完成。

## 2. 制作方法拆解（可复现路径）

### 2.1 素材层 · 5 类

| 类 | 来源 | 备注 |
|---|---|---|
| 角色立绘 PNG（全身 or 半身） | AI 生图（NovelAI / SD / Midjourney / GPT-image-2）或客户提供 | **透明底 or 白底 + 抠图**；单角色分 3–5 姿势/构图；**vertical 高分辨率**（本案客户 PNG 5120×9104 就是这个规格） |
| 环境背景 | AI 生图 or 图库 | 每段一张；同调色板 |
| 光效素材 | 光束/眩光/粒子 PNG/MOV | 用 [Motion Elements] / [Videohive] / 剪映内置素材 or CC0 |
| 大字字体 | 思源宋体 Heavy / 汉仪尚巍手书 / 方正兰亭黑 Extra-Bold | 中文明朝/宋体系为主，副 tag 用等宽 |
| DV UI 边框 | 一次做好的 PNG 模板 | 底部时间码用**动态计数**（`drawtext=text='%{pts\\:hms}'`） |

### 2.2 合成层 · 3 种可选实现

| 方案 | 工具 | 优点 | 缺点 | 适合场景 |
|---|---|---|---|---|
| **A. CapCut 剪映（推荐）** | 剪映电脑版 | 有 kinetic 字幕预设 / 光效 / 滤镜；一键节拍分析；出片快 | 精度到 100ms；UI 边框需自制 PNG | **本类客户活儿默认路径**；1–2 天 |
| **B. Adobe After Effects** | AE + 免费模板（envato/motion-array） | 精度到 1 帧；伪 DV UI 可直接买模板 | 上手成本；渲染慢 | 客户预算高 / 要求电影感 |
| **C. FFmpeg + Python 脚本** | 本项目 `pipeline/` 现有能力 | 可批量、可版本控、可参数复用 | 大字弹入/粒子/DV UI 需要拼 filter_complex，工作量比 A 大 | 客户委托做**同一账号系列 10+ 条**时批量出片 |

**默认走 A。** 只有客户明确要一批同套路系列（>10 条同风格），才考虑 C。

### 2.3 15 分钟一条的最短路径（无本引擎能力介入版）

1. 客户或客户委托画师给 4–6 张立绘（vertical PNG，透明底最佳）
2. 客户或客户找 4–6 张环境背景（横版 16:9）
3. 剪映导入歌曲 → **节拍检测**打点
4. 每 8–15s 一段人物特写：立绘居中大 → 轻推 kb 关键帧
5. 击点处：加大字幕（预设"kinetic 弹入"）+ 括号副 tag（额外小字文本框）
6. 副歌段：叠 REC 取景框 PNG + 底部动态时间码
7. 加光效素材 3–5 处（overlay / screen 模式）
8. 加色差 / 磨皮滤镜 → 出片

### 2.4 借用本引擎能力时的接口

只有以下环节值得走本项目 `pipeline/`：

| 场景 | 走本引擎 | 备注 |
|---|---|---|
| 立绘不够，需 AI 生更多角度 | `pipeline/gen_*_stills.py` 模仿 D06 结构 | 用 GPT-image-2-1k `/v1/images/edits` 挂客户立绘 PNG 锁脸 |
| 环境背景批量 AI 生图 | 同上 | 独立 shots，锁色板到 palette |
| 大字歌词 SRT/ASS 自动烧字 | `ffmpeg` + libass（`/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`） | 竖排大字用 ASS `\an7\fs120` 系样式 |
| 拼接与音画同步 | 参考 `pipeline/assemble_d06_wuxia.py` 结构 | `-map 0:v:0 -map 1:a:0` 强制音轨（防素材自带音轨污染） |

**不走本引擎的**：粒子系统、DV UI 帧动画时间码、光效叠加、色彩分级——这些剪映做更快，别硬拗 `filter_complex`。

## 3. 通用出片 SOP（客户借用能力时）

### Phase 0 · 需求接单

- [ ] 拿到**歌曲 mp3/wav** 和**分词稿**（哪句谁唱）
- [ ] 拿到**角色立绘 PNG**（每角色至少 1 张全身/半身，vertical）
- [ ] 拿到**画面调性描述**（水墨/赛博/唯美，颜色，风格参考图）
- [ ] 拿到**版式**（横版 / 竖版）与**时长**（跟原曲 or 剪到副歌 30–45s）
- [ ] 拿到**投放平台**（抖音/小红书/B站/YouTube；决定水印格式）

### Phase 1 · 分镜拆解（30 分钟）

按歌词分词稿把时长划成 **4–8 段**（每段 6–15s）：
- 独唱段 → 该角色单独 dominate
- 合唱段 → 双人 / 群像
- 副歌 → 情感高点，DV UI 上，粒子放大

产出：一个简单的 `shotlist.md`，每行 = 时段 / 主视觉 / 大字歌词 / 背景 / 光效 / DV UI on-off。

### Phase 2 · 素材准备

- 立绘：客户给的直接用；不够则 AI 补
- 背景：AI 生或图库；每段一张
- 光效素材：一次性备好 5–8 个 MOV/PNG（whoosh 光带、粒子、雪、光斑、chromatic 色差）
- DV UI PNG：一次性做好，多个项目复用
- 字体：项目复用 `思源宋体 Heavy` + `汉仪尚巍手书`

### Phase 3 · 剪映合成（60–120 分钟）

按 §2.3 的最短路径出片。**必查项**：
- 大字击点误差 ≤ 3 帧
- 每段人物立绘至少一个"轻推 zoom"关键帧（防止死画面）
- DV UI 帧的时间码是**动态计数**不是静图
- 分辨率按客户版式（横版 1920×1080，竖版 1080×1920）

### Phase 4 · 交付

- MP4（H.264 High Profile，1080p，5–8 Mbps）
- 附件：分镜稿 + 立绘 / 背景源文件（客户可能后续要改）
- 水印格式与客户账号一致（本参照片是 `Ly.<角色名>`；D07 需按客户告知）

## 4. 与项目主旨的分线原则（重要）

本类活儿产出**不进** SYSTEM.md 的能力全景表；**不算**引擎主线内容。存放规则：

| 内容 | 位置 |
|---|---|
| 通用 playbook（本文） | `publish/2026-W30/D07/` 下（各周独立） |
| 客户素材（立绘、歌曲、docx） | `publish/2026-W30/D07/` 下 |
| 合成脚本（如决定走 C 方案批量） | `pipeline/client_projects/<slug>/` 独立命名空间，**不放**在 `pipeline/` 顶级 |
| 出片 mp4 | `tmp/d07_<slug>/` 出片 + `publish/2026-W30/D07/final/` 交付 |

**禁止**：把这类模板视为引擎的候选实现（不进 SYSTEM.md §4.2 候选清单）；不在 `templates/` 建可复用工种；不写进 CLAUDE.md 铁律。理由：不同客户风格差异极大（水墨 vs 赛博 vs 唯美），可复用度低，硬做工种只会污染主线判断。

## 5. 反例（不要这么做）

- ❌ 把参照片叫"Live2D"，然后去搭真的 Live2D 骨骼工作流——**它不是**，是立绘 + 视差 + 大字。硬上 Live2D 是 10 倍工作量、10 倍成本、10 倍工具链坑。
- ❌ 把它塞进 `pipeline/p004_video/` 或者装作它是本引擎的一个 P00X 候选——它是客户活儿，不算引擎路线。
- ❌ 硬用 `filter_complex` 造粒子/眩光/色差——比剪映慢 20 倍，效果还差。
- ❌ 用项目主线的"两道门"（内容门/形式门）审这类客户活儿——客户没有观众数据 KPI，只有客户满意 KPI。
- ❌ 大字歌词击点不对齐节拍——观众直觉察觉，"这不专业"。误差 ≤ 3 帧硬标准。
- ❌ 全片单一固定机位不加内镜运动——即使只是 2% zoom-in 也必须给，否则是"PPT"。
