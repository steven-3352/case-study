# W26D09 · 动效技术计划

## 适用性

本条使用 GSAP 2.5D 动效，首镜可尝试轻 Three/Web 3D 任务风暴；如果 Three 首屏可读性不够，降级为纯 GSAP 卡片风暴。

高级动效服务的数据指标：

- 0–3s 停划：任务风暴比静态工具截图更能表达普通人的混乱。
- 完播：第 6 镜混乱分拣成小工具，给中后段变化。
- 理解：中段坚持 2D UI，避免 3D 抢走信息。

## 可读性

- 9:16 画布，主文字不小于 64px。
- 3D/2.5D 卡片只承载短词：表格、文案、文件、小网页。
- 方法论文字全部用 2D 层：现在怎么做 / 哪里重复 / 想要结果。

## 资产

- 不依赖外部图片/视频。
- 所有画面使用 HTML/CSS/GSAP/必要时 Three 生成。
- 表格和工作台为仿真解释画面，不冒充真实 Codex 后台。

## 导出

- 走 `pipeline/p004_video` 类 HTML 截帧 → mp4。
- 模板命名 `d09_*`，不得复用 D08/P004 暗色终端族。
- 口播和字幕后置合成，外发默认含 BGM。

## 风险

| 风险 | 控制 |
|------|------|
| 3D 太花 | 首镜只保留 4 类任务卡，背景简洁 |
| 像教程 PPT | 第 2 镜错误 prompt、第 6 镜小工具结果制造变化 |
| 真实 UI 过时 | 使用仿真工作台，不展示具体产品入口 |
| 普通人看不懂代码 | 工作台展示动作，不展示代码长段 |

## 结论

允许进入 storyboard，但必须先做 `d09_task_storm` 首镜样帧检查。若首帧 1 秒内看不懂“不会代码也能处理重复事”，降级为 2D/GSAP 卡片风暴。
