# W26D09 · 多 Agent 讨论室

## Round 1 · 立项

**编导：** 这个选题可以做，但不能做成 Codex 教程。账号主线是“小老板烦事 → 能跑的小系统”，所以本条必须讲“普通人如何把重复事交给 Codex”，不是讲产品入口。

**选题深挖师：** 痛点不是不会代码，而是不知道怎么开口。用户常问“帮我做个系统”，但缺流程、输入、输出。

**运营：** 评论要用四选项，不要问开放大问题。表格、文案、文件、小网页四个选项足够低门槛。

**决议：** 立项通过。标题方向：“普通人第一次用 Codex，别先让它写系统”。

## Round 2 · 洞察

**内核提炼师：** 一句话价值锚是“普通人用 Codex 的第一步不是学代码，而是把一件重复事讲清楚”。

**领域专家：** 案例选客户表格合理，因为它有输入、重复动作、输出结果，能展示“小工具”。

**事实校验员：** 官方 Codex manual 未成功拉取，发布前必须复核。当前脚本不写入口、订阅、权限，只讲使用思路。

**决议：** 允许写脚本，但具体产品 UI/入口不得进入口播。

## Round 3 · 脚本

**编剧：** v0 太像功能介绍，淘汰。vB 情绪更强，但“像老板”理解成本高。推荐 vA：先说“第一句话问错了”，再给三步方法。

**纪录片导演：** vA 有前后变化：错误问法 → 正确输入 → 小工具结果。中段要有具体表格案例。

**留存与互动设计师：** 结尾必须四选项。不要用“你会不会用 Codex”，太泛。

**决议：** 选 vA，评分 88–90。进入形式策略会。

## Round 4 · 形式策略

**形式策略官：** 首镜用任务风暴服务 3s 停划；中段用 2D 卡片和仿真表格服务理解；高潮用流程分拣服务完播。

**动效技术导演：** 允许轻 Three/Web 3D 试首镜，但必须可降级到 GSAP 2.5D。真实 Codex UI 不用，避免过时。

**视觉设计：** 用浅色工作台，避免 P004 黑金终端族。文字要大，普通人不能被代码吓退。

**决议：** 进入 storyboard v1；render 前必须补独立 scorecard 和官方口径复核。
