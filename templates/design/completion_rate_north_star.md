# 完播率北极星 · 一切为了数据

> **最高优先级指标：** `completion_rate`（完播率）+ `completion_3s`（3 秒完播）  
> 从选题到投后复盘，所有工种对「观众会不会划走」负责，不是对「文件齐不齐」负责。

## 1. 为什么前 3 秒决定一切

抖音/小红书竖屏信息流里，用户用拇指投票：

| 时刻 | 系统在量什么 | 我们须设计什么 |
|------|--------------|----------------|
| **0–1s** | 是否停划 | 人设一眼可辨 + 主信息大字/强画面 |
| **1–3s** | 是否继续看 | 冲突/数字/反差落地，音画同拍 |
| **3–15s** | 是否建立期待 | 钉子场景 + 原话，非方案朗读 |
| **中段** | 是否拖沓 | 每 5–8s 视觉或信息变化 |
| **末 5s** | 是否完整看完 | CTA 口播完整进片，不裁切 |

**铁律：** 前 3 秒不是「加个钩子字幕」——须拆解**同行业热门**的人设、镜头、音乐，再结合**本账号特点**做差异化停划设计。

## 2. 北极星指标 · 贯穿全链路

```
立项                    生产                    外发前                 投后 48h
───                    ───                    ─────                 ────────
编导定完播目标    →    留存表 0–3s 设计   →    分析师预估完播区间  →    actual 回填
网络调研拆同行    →    编剧钩子落前 3s    →    听片核验 3s 停划   →    evolution 调下条
形式选型不撞同质  →    分镜首镜停划镜头   →    forecast go/no-go   →    完播<25% 触发改法
声音选曲对标情绪  →    BGM 0–3s 不盖人声  →    cover 用停划帧      →    3s 低则重做首镜
```

| 环节 | 负责工种 | 完播相关产出 | 门禁 |
|------|----------|--------------|------|
| 调研 | 网络调研员 | `insights/hook_benchmark.md` ≥2 条同行拆解 | pre_render |
| 立项 | 编导 | `retention_beat_sheet.md` 完播目标 + 3s 设计 | pre_render |
| 脚本 | 编剧 | 钩子句 ≤12 字落 0–3s 口播 | script_review |
| 留存 | 留存设计师 | 节拍表 0–3s 行 + 5–8s 变化 | pre_render |
| 形式 | 动效设计师 | 首镜 WOW = 停划镜头，非 catalog 标配 | approve |
| 声音 | 声音设计师 | `audio_plan.yaml` BGM 情绪曲线对齐 0–3s | pre_render |
| 分镜 | 动效分镜师 | storyboard 第 1 镜 duration ≤4s | pre_render |
| 预估 | 平台表现分析师 | `pre_publish_forecast.md` 3s + 完播区间 | approve |
| 听片 | 编剧 + 留存 | `vo_listen_notes.md` 0–3s 停划评判 | approve |
| 投后 | 编导 + 进化 | `performance.yaml` actual → overlay | 48h 导入 |

## 3. 同行拆解 · 看什么（≥2 条热门参考）

每条参考须可打开（URL 或账号+标题），拆四列：

| 维度 | 拆解问题 | 可借鉴 | 我们差异化 |
|------|----------|--------|------------|
| **人设** | 谁在说、什么身份、信任感从哪来 | | 小老板系统改造者，非 AI 教程号 |
| **镜头** | 首镜景别、运动、字幕大小、几 cut | | 结合本条钉子场景 |
| **音乐** | BGM 情绪、入点、是否压人声 | | 对齐 audio_plan mood |
| **3s 停划** | 用什么留住拇指（数字/反差/问句） | | 本条钩子句 |

模板：`templates/insights/hook_benchmark.md`

## 4. 结合自身特点 · 不可照搬

本账号（当前皮肤）差异化：

- **项目结果先于方法论** — 先给「改造后长什么样」，再讲原理
- **钉子场景** — 谁、何时、在哪、烦什么（非「小老板都烦」）
- **真实系统画面** — Excel/微信/表格/流程，非抽象图标
- **讨论型 CTA** — 促评论场景共鸣，非扣 1 / 私信导流

同行技巧拿来的是**节奏和停划结构**，不是抄人设和文案。

## 5. 数值口径（与投后闭环）

| 指标 | 字段 | 参考线（抖音 · 45–60s 演示型） |
|------|------|--------------------------------|
| 3s 完播 | `completion_3s` | ok ≥55% · 低 <45% |
| 完播率 | `completion_rate` | ok ≥40% · 低 <25% |
| 均播时长 | `avg_watch_s` | 目标 ≥ 片长 × 完播率 |

投后：`import_metrics_48h.py` → `evolution_apply.py` → 下条 `evolution_overlay.md` 须写清「上条 3s/完播教训」。

## 6. 完播差 → 改法优先级

| 信号 | 优先改 | 禁止 |
|------|--------|------|
| 3s 低、完播低 | 首镜镜头 + 钩子字幕 + BGM 入点 | 只改标题不改片 |
| 3s 高、完播低 | 中段节奏、5–8s 变化、砍冗余 | 为卡时长删叙事 |
| 完播 ok、互动低 | CTA 问句、评论区埋点 | 硬广导流 |
| 与上条同质 | 形式 v2 重做首镜语法 | 换 d{NN}_ 文件名不换视觉族 |

登记：`ops/rules.yaml` R03/R07 · `docs/design/FORM_FAIL_LOG.md`
