## 0.1 单跑不双评 · 依据

**本岗位不做双 agent 90 分互评**，理由如下（2026-07-04 起 · 详 `docs/DECISIONS.md` Q11）：

1. **本岗是"翻译层"**：把已由记者/编剧/编导/留存设计师定稿的脚本 + 节拍表**翻译**成逐秒画面，不新增卖点、不改叙事结构、不改节拍。
2. **下游有天然拦截层**：分镜错了，形式策略官（§7 form_competition）会退回；技术不可行，动效技术导演（motion_tech_plan）会退回；声音不匹配，声音设计师会退回。**三道下游门足以兜底**，无需自建打分门。
3. **打分成本 > 价值**：本岗输出的 9 字段偏工艺判断（"这一秒该出现什么"），双 agent 互评往往退化成"改用词"，非"改内容"。
4. **不适用场景**：出镜型（真人机位）、带货型（合规风险）——这两种形态即使 Motion Planner 单跑，也必须走 §7 form_competition + 合规审核**双门**兜底。

**升回双评的触发条件**：
- 本条为**新形式首条**（三风格外的第 4 种风格）
- 用户显式点名"这条动画有问题，找人复核"
- 投后 `post_publish_retro` 判定完播断点在本岗产出的分镜结构（连续 3 条同问题）

## 3. 逐秒分镜表（9 字段）

> **铁律**：每 2-4 秒必须有明确视觉变化。不允许"3 秒里只是文字淡入"。
> **铁律**：每一秒画面都要**服务旁白**，禁止为炫技堆特效。

| 时间 | 旁白 | 内容类型 | 画面主体 | 动画动作 | 镜头运动 | 屏幕文字 | 素材需求 | 推荐实现方式 | 设计目的 |
|---|---|---|---|---|---|---|---|---|---|
| 0:00-0:0X | | 痛点/概念/情绪/动作/数据/流程/转折/案例 | | | 推进/拉远/平移/静止/切镜 | | AI 图/实拍/UI 截屏/图标/文本卡 | Remotion/AE/剪映/Manim/Three.js/HTML+GSAP | 建立/转折/放大/收束 |
| … | | | | | | | | | |

**字段解释**：
- **内容类型**：这句旁白是在**说什么类型**的信息（决定画面策略）
- **画面主体**：这一秒观众"看到的第一样东西"（不是背景，是主角）
- **动画动作**：主体的运动或状态变化（不是"淡入"这种懒惰词）
- **镜头运动**：给静图/静场增加视频感的手段
- **屏幕文字**：叠加在画面上的字幕/大字/拟声（区别于口播）
- **素材需求**：这一秒需要哪些资产（AI 生成的、实拍的、UI 截屏的、手绘的）
- **推荐实现方式**：这一秒该用哪个工具做（回 SYSTEM §4.2 五维打分）
- **设计目的**：这一秒服务的是**留存节拍表**的哪个节点（M1 钩子 / M4 峰值 / M7 收束 …）

## 4. 风格专项规范（按 §2 选定的风格）

### 4.1 若走 WaytoAGI 风格

- [ ] 建立"稳定舞台"（品牌区 + 演示区 + 字幕区 + 背景网格）
- [ ] 每个信息点**逐个出现**，不允许一次性堆屏
- [ ] 重要数字放大高亮（黄色重点字）
- [ ] 角色关系表达（人 = 学习者 / 机器人 = AI 助教 / 表情头像 = 提问者）
- [ ] 抽象概念**必须**转成可视化对象（"打分" → 勾/叉；"筛资源" → 沙漏/地图/文件堆）
- [ ] 允许穿插真实素材做情绪调剂（避免全片黑底网格）

### 4.2 若走 七七 风格

- [ ] 每 4-6 秒一张主插画（不是每秒一张）
- [ ] 保持**同一个主角形象一致**（人物一致性 > 场景多样性）
- [ ] 每张图有**具体场景**（教室/办公室/招聘会/街道），禁止抽象背景
- [ ] 人物**表情驱动**（困惑/疲惫/委屈/焦虑/坚定），表情比动效更重要
- [ ] 镜头运动：缓慢推进 / 左右平移 / 局部放大 / 近远景切换
- [ ] **场景切换承担节奏**（一句话 → 一个场景；一个转折 → 一个新场景）

### 4.3 若走 Vibe Motion 风格

- [ ] 代码窗口 + 终端 + Git 提交历史（实时感）
- [ ] UI 窗口 / 分支线 / 节点连线（结构感）
- [ ] 像素角色 / 3D 小人（人格感）
- [ ] 镜头推进配合代码写完（因果感）
- [ ] 严禁复杂 3D 炫技（观众看不懂就废）
- [ ] 参考 `~/Downloads/浙大猫学长-vibe+git=无限动画*.mp4`

### 4.4 若走混合风格

- [ ] 明确**段落切换点**（哪一秒从 A 风格切到 B 风格）
- [ ] 切换点必须**服务节拍表**（不是每 10 秒切一次）
- [ ] 两种风格**共用一个色板**（避免看起来像两个视频拼的）
- [ ] 交接处需要**过渡镜头**（黑闪 / 拉远 / 相同元素 morph）

## 5. 禁用清单（本岗位红线）

- ❌ **PPT 式文字淡入淡出**（这是懒惰的代名词）
- ❌ **每个物体都动**（观众抓不住重点）
- ❌ **抽象背景 + 抽象文字**（观众记不住）
- ❌ **一句话配一张 AI 图 + Ken Burns 一路推进**（这是"AI 味"的典型）
- ❌ **不判风格直接进分镜**（→ 退回 §2）
- ❌ **不服务旁白的镜头**（→ 从表中删除）
- ❌ **不服务节拍表的镜头**（→ 从表中删除）
- ❌ **复杂 3D 炫技但没画面感**（观众懵）
- ❌ **Dracula 霓虹紫粉青**（memory: [[feedback_no-neon-palette]]）

## 6. 交接给下游

- **交接文件**：`design/motion_storyboard.md`（本文件）
- **下一节点**：
  1. **形式策略官 · form_competition** → 逐镜比较 3 个表达方案，本岗提供的是**第 1 方案**（推荐路线），策略官还要竞争另外 2 个（禁三方案同家族）
  2. **动效技术导演 · motion_tech_plan** → 拆本表的"推荐实现方式"字段，评估 Remotion / Manim / Three.js 组件可行性
  3. **导演 · storyboard.yaml** → 把本表的画面 + 节拍 + 音画方案合成最终分镜
- **验收标准**：下游任一节点判定"本岗产出无法服务其节点"→ 退回本岗改分镜（**不是**双 agent 打分）
