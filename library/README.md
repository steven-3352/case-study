# library/ · Tonbirds Content Engine 长期资产库

> **这是什么：** 内容制作的长期知识资产 · 与"单次制作产出"（在 `publish/<项目名>/` 下）区分。
>
> **为什么单独放：** 领域知识/受众痛点/真实原话/形式家族/视觉 token 这类东西是"写一次很多条选题吃"的长期资产 · 不该每条选题重造。把它们从 workflow 里抽离 · 独立触发 · 独立入库 · 制作时"查库不重跑"。
>
> **触发时机：** 仅用户手动命令 · 参见下方"触发协议"。

---

## 目录

| 子库 | 存什么 | 谁读 |
|---|---|---|
| `domains/` | 领域知识（业务地图 / 竞品对照 / 生态数据） | 制作层立项 / 形式策略 / 视觉语言 |
| `audiences/` | 受众类型定义（人群 / 场景 / 姿势 / 心理位移原型） | 制作层选题深挖 / 编剧 / 留存节拍 |
| `quotes/<domain>/` | 真实公开原话按话题 tag 分类（含 [一手]/[二手] 标签） | 编剧 · 形式策略 · 内核提炼 |
| `subcultures/` | 亚文化圈层字典（梗/雷/黑话/仪式） | 编剧 · 运营 · 视觉设计 |
| `visual_language/` | 视觉设计语言候选池（符号 / 禁用清单 / 动态元素） | 视觉语言策展 · 分镜 · 封面 |
| `motion_tech/` | 动效实现技术家族对照（可行性 / 成本 / 天花板） | 动效技术导演 · 形式策略 |
| `formats/` | 内容形式家族清单（现存做法 / 数据杠杆 / 表达上限） | 形式策略 · 留存节拍 · 编剧 |
| `methodology/` | 复用方法论（验证方法 / 提炼方法 / 打分方法） | 全流程 |
| `topics/` | 选题库（含教训 · 附本次独有产出路径索引） | 制作层立项 |

## 触发协议

**A 层库维护员的触发**：**仅用户手动命令**

- ✅ 用户明说 → 触发：
  - "帮我研究一下 XX 领域" → 起 domains 库维护员
  - "扒一批 XX 主题的原话" → 起 quotes 库维护员
  - "补一下 XX 形式家族" → 起 formats 库维护员
  - "整理 XX 亚文化梗雷" → 起 subcultures 库维护员
  - "抽 XX 视觉 token" → 起 visual_language 库维护员
- ❌ 默认关闭：
  - 定期/定时任务（不每周自动重扒）
  - 制作层遇缺项时自动反射（B 层报告缺项 · 不自动补库 · 等用户拍板）
  - 材料驱动（`material/` 新增文件不触发库提炼）

**B 层制作遇缺项时的动作**：
- 报告缺项 → 等用户拍板"是补库还是靠常识往下"
- 不自动触发 A 层
- 库缺项属"记录在案的信息缺口"，不属"流程 fail"

## Frontmatter Schema（每份库文件必带）

```yaml
---
name: <slug>                              # 文件名 slug · 全库唯一
type: domain | audience | quote | subculture | visual_language | motion_tech | format | methodology | topic
last_updated: YYYY-MM-DD
source_projects:                          # 这份库文件来自哪些真实项目的抽取（可追溯）
  - publish/<project>  (<version> · <date>)
tags: [<tag1>, <tag2>, ...]               # 用于按 tag 检索
reuse_scope: <这份库文件的复用边界 · 哪些赛道/选题能吃>
freshness_horizon: 30d | 90d | 180d | event-driven   # 多久需要复审
---
```

## 文件结构（每份库文件推荐）

```markdown
# <标题>

## 摘要 (≤ 100 字 · 未来查库者先读这个)

## 内容
<主体 · 分段>

## 溯源
- 抽自 <原文件路径> §<段落>
- 二次来源: <其他相关引用>

## 复用注意事项 (optional)
<警告 · 例如"CV 圈层梗有 6-12 个月时效滞后风险"这类>
```

## 与 `publish/<project>/` 的关系

- **不互相取代 · 是两个视角**
- 库 = "通用视角提炼"（抽出可复用部分）
- publish/ = "本条视角原始产出"（保留本条独有细节 + 上下文）
- 抽库不删原文件（`publish/语音厅/insights/*.md` 全部保留）

---

## 与 `queue/topics.yaml` 的关系

- `queue/topics.yaml` = 待做选题的**运行时队列**（一句话 · 状态 · 优先级）
- `library/topics/*.md` = 选题库的**详细文档**（含教训 · 独有产出路径索引）
- 两者互补：一个是"待办清单" · 一个是"档案柜"
